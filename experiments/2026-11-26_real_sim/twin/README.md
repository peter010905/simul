# 실물 주행과 Gazebo 경로 비교

VM의 비교 보드는 [실물·시뮬 경로 비교](http://192.168.252.2:8782/)에서 연다. 사용자가 표시한 16개 책상을 위 5개, 가운데 3개씩 두 묶음, 아래 5개로 배치했다. 각 책상에 같은 크기의 상판과 독립 다리 충돌 형상 4개가 있다. 실물 주행 8회의 SLAM·바퀴 경로와 영상을 조회할 수 있다.

자동 주행 비교의 기준 기록은 `20261125T174857-2f02f6e167`이다. 실물에서 쓰인 v1.5.2.43.1 정책, 가중치와 Nav2 설정을 격리된 Jazzy Gazebo로 가져왔다. 보드에서 다른 기록의 정책을 선택하면 같은 재구성 시험장과 출발 자세에서 새 실험을 실행한다. 그때는 해당 정책이 과거 다른 배치에서 기록한 실물 경로에 대한 오차를 집계하지 않는다. 자동 위치 정합을 승인할 근거가 부족한 다른 기록은 출발 자세 기준으로 따로 열람한다.

## 비교 기준

- 실물은 `mission_started`, 시뮬은 시작 서비스 응답을 0초로 사용한다. 위치와 방향을 시작 시점에 고정한다. 궤적에 맞춰 회전하거나 시간을 늘여 맞추는 보정은 하지 않는다.
- 실물 위치는 지도 좌표의 SLAM 추정치다. 바퀴 오도메트리를 별도로 확인할 수 있다. 시뮬 위치는 Gazebo의 독립 좌표다.
- 공통 구간을 0.5초 간격으로 비교하고 2초를 넘는 관측 공백을 제외한다. 위치 RMS, 95백분위, 25cm 이내 비율, 방향 오차, 두 경로의 길이, 유효 표본 비율을 표시한다. 같은 목표 달성과 같은 단순 시간 제한 종료를 구분한다.
- 실물에서 위치를 복원한 마커는 ID 42다. 10분 내 마커 3개 완주율은 이 기록에서 비교할 수 없다. 나머지 두 마커의 위치는 알 수 없다. 복원 가능한 마커만 장면에 두고 정책은 원래의 탐색 임무를 수행한다.
- 고정 책상만 있는 초기 비교와 반복 LiDAR 반사를 추가한 비교를 남겼다. 초기 비교 두 회는 시뮬 전용 회전 설정과 잘못된 마커 인쇄 방향을 사용했다. 마커 검출 성능 비교에 사용하지 않는다. 실물 설정판은 인쇄 방향, 실측 기반 크기, 시작 바퀴 좌표, 실물 모드의 회전·필터·SLAM 설정을 반영한다.
- 실물 책상 크기·통로 폭은 추정값이다. 상판 돌출 8cm와 추가 반사체 높이 30cm는 모델 가정이다. 유리 투과, 움직이는 의자와 사람, 노트북 미끄러짐, 모든 마커 위치와 조명은 실측 복원되지 않았다.

## 파일과 재현 순서

이 도구는 ROS 2 Jazzy VM에서 실행한다. 실물 원본 rosbag, 검토한 다리 좌표, 생성 지도, 영상은 VM에 보관한다. 아래 파일 순서대로 단계를 반복할 수 있다. 각 Python 명령의 위치 인자는 `--help`로 확인한다.

1. `build_scene.py`가 원래 시험장 SDF, 수동 검토 SLAM 자료, 해당 실물 로그에서 16개 책상, 실물 출발 자세, 추정 마커와 실물 경로를 만든다. 이미지의 모서리와 지도 사이의 대응은 해당 실물 기준 기록에 귀속된다.
2. 상위 폴더 `persistent_scene.py --use-slam-pose`로 지도와 LiDAR를 시각별 SLAM 자세와 정적 센서 변환으로 연결한다. `scan_scene.py`는 재관측된 점유 구간에만 별도 시뮬 충돌 형상을 추가한다.
3. `library.py`와 `camera_strip.py`로 실물 기록·카메라 색인을 만든다. `registration.py`는 초기 스캔으로 구한 복수 자세를 이후 스캔으로 검사한다.
4. `hardware.py`와 `stage_library.py`가 각 실물 정책을 별도의 시뮬 워크스페이스로 복사·빌드한다. 원본 정책의 가중치 해시를 확인하고 실물에서 기록한 Nav2 파일을 적용한다. 보관된 YAML과 설치본의 파일별 일치 여부도 남긴다. 실물 주행 시점 소스 커밋은 8개 기록 모두 비어 있어 당시 소스 전체의 동일성은 입증할 수 없다. 실물 도메인에서는 이 복사본의 시작을 거부한다.
5. VM의 `~/classroom-twin`에서 `bash code/twin/trial.sh scene16-parity ~/twin43_hardware_ws "$PWD/trial-track-new"`로 같은 자율 정책을 실행한다. 보드 버튼도 같은 실행기를 사용한다. 출력 폴더 이름은 실행마다 새로 지정한다. 공식 시험 관측기가 로그를 기록하고 정책의 실제 움직임을 평가한다.
6. `service.sh`로 보드만 시작한다. `report.py`가 끝난 주행의 JSON 지표와 경로 그림을 만든다. `TWIN_FIXTURE=… python3 -m unittest discover -s code/twin -p test_twin.py`로 16개 책상·64개 다리, 대칭, 실제 SDF 인쇄 방향에서의 ArUco 판독과 비교 계산을 검증한다.

## 카메라와 LiDAR 검증

실물 영상의 특징점 이동과 로봇의 회전량을 대조해 가로 화각을 추정한다. `optics.py`로 주행별 추정치를 구하고 `optical_stage.py`는 기준 주행과 마지막 5m 주행을 제외한 여섯 기록으로 렌더러의 가로 초점거리를 보정한다. 세로 화각은 실물 카메라가 발행한 값을 따른다. `optical_probe.py`로 Gazebo가 내보낸 실제 프레임에서 다시 측정한다.

`scan_signature.py`는 같은 여섯 실물 주행 각각에서 유효한 반사가 거의 없었던 고정 방향을 분석한다. 기준 주행과 마지막 5m 주행에서 따로 확인된 방향만 `scan_stage.py`의 별도 Gazebo 센서 모델에서 사용한다. `laser_check.py`는 실물에 기록된 자세에서 장면의 충돌 형상에 수평 광선을 쏘아, 환경 복원 자체가 만든 거리 오차를 측정한다. 센서 수신 각도 보정과 위치에 따라 달라지는 유리·사물 반사는 독립적인 문제다.

기준 기록의 첫 계획 스냅샷을 `reference-decision.npz`로 연결하고 `comparison.first_decision`의 반환값을 `reference_decision.json`에 저장하면 보드의 첫 목표 비교가 활성화된다. 각 설정의 첫 지도, 자유 공간, 장애물과 선택 후보를 같은 축척으로 확인할 수 있다. 광학·LiDAR 보정 사본을 보드에 등록할 때는 `stage_library.py --optical … --scanner …`를 사용한다.

`map_layer.py --anchors …`는 최종 실물 SLAM을 시험장 좌표계로 변환한다. 보드에서 ‘책상 다리 대조’를 켜면 모델의 다리 64개와 맞춤에 사용한 실물 대응점 14개를 함께 볼 수 있다. 위치 오차 13cm는 이 14개 점에 대한 값이다.

‘출발 주변 재관측 반사’ 배치는 `start_surfaces.py`에서 만든다. 출발 후 3초까지의 서로 다른 관측 자세 두 곳 이상과 30초 이후 자세 두 곳 이상에서 각각 10cm 이내로 지지한 최종 점유 셀만 사용한다. 출발 주변 3.5m 안의 이 셀들을 8cm 격자에 얹고 이어진 셀만 묶는다. 바퀴와의 초기 겹침을 검사한다. 시뮬 런타임에는 완성된 정적 장면을 사용하며 원본 실물 명령이나 다음 위치를 주입하지 않는다. 센서 거리 검증에 사용한 4~8초 스캔은 이 재관측 투표에서 제외했다. 최종 SLAM 자체는 같은 주행에서 생성되었으므로 독립 시험장의 검증으로 해석할 수 없다.

## 다른 출발 위치와 재실행

`multi_map.py`는 다른 기록의 마지막 SLAM 지도 전체를 시험장에 맞춰 본다. 1.5m 공간 블록의 3분의 1을 맞춤에서 보류해 20cm 이내의 일치율을 측정하고, 중앙의 고정 구조 근처와 경쟁하는 다른 방향도 검토한다. 7개 기록의 후보를 보드에서 ‘추정 위치’로 열어볼 수 있다. 추정 위치로 그린 경로에는 주행 재현 오차를 부여하지 않는다. 정식 비교는 사용자 도면과 실제 SLAM 대응점을 확보한 기준 기록에서 수행한다.

같은 장면·정책·시간 예산으로 두 번 실행했으면 보드에서 두 Gazebo 경로 사이의 오차도 볼 수 있다. 첫 여섯 목표의 선택 시각과 유형, 출발점에서 처음 1·3·5m 떨어진 시각, 같은 ID의 첫 등록 시각을 비교한다. 모델을 바꿀 때는 단일 회차에서 첫 목표가 우연히 맞는 경우까지 포함해 결과를 해석해야 한다.

실물과의 비교는 공통 시간의 91.5%에서 유효한 표본 1,061개를 사용했다. 시뮬끼리도 11초부터 0.5m 이상 벌어지는 구간이 생겼고, 시뮬 간 RMS는 12.12m였다. 실물은 약 38.7초에 번호가 읽히지 않은 인쇄물 후보를 향했다. 두 시뮬은 세 번째 목표로 계속 미탐색 구역을 골랐다. 동일한 경로와 소요 시간이 재현됐다고 볼 수 없다.
