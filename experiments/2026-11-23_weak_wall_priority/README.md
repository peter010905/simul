# 작은 원거리 단서 우선 검증: Mixed v1.5.2.11

## 변경 이유

같은 시험 배치 `map-417608489`에서 v1.5.2.10은 카메라로 보지 않은 먼 벽을 점수에 넣어도 서쪽 벽의 ID 768을 놓쳤다. 600초 동안 2/3개만 검증했고 92.44m를 이동했다. 이전 v1.5.2.2의 성공 기록에는 여러 프레임에 남은 작은 흑백 단서를 따라 그 벽으로 이동한 결정이 있었다. 최근 정책에서는 상자 연속 관찰, 새 구역, 일반 벽 목표가 이 직접 단서의 검증보다 먼저 선택될 수 있었다.

v1.5.2.11은 기존 `WallBearings`의 다중 프레임, 지도상 벽 대응, 안전한 관찰점, 시도 횟수 제한을 그대로 사용하며 그 선택 순서만 일반 목표보다 앞에 둔다. 상자의 관찰 완료 기준, Nav2, footprint, inflation, 충돌 회피, 카메라 해상도 및 프레임 설정은 변경하지 않았다. 상자의 남은 면은 보류 상태로 남는다. 별도 후보이며 실물 정책을 교체하지 않았다.

## 독립 시험 배치

고정 책상 시험장의 Gazebo Jazzy 주행이다. 앞의 세 배치는 추가 상자 3개와 마커 3개(상자 2, 벽 1)를 둔 비교 배치다. 마지막 두 배치는 미리 결과를 보지 않고 정한 시드로 만든 **별도 스트레스 시험**이다. 네 번째에는 ㄱ자 장애물이 섞이고 마커 3개가 전부 벽·기둥에 붙었으며, 다섯 번째에는 추가 장애물이 없고 마커 3개가 전부 벽에 붙었다. 따라서 이 둘을 ‘상자만 있는 동일 시험 조건’으로 묶어 평균 비교하지 않는다. 각 행은 별도 출발 자세에서 600초 제한으로 실행했다. 성공은 **세 ID의 개별 판독과 각 마커의 실제 1.5m 이내 접근**을 모두 요구한다. 범퍼 접촉과 잘못된 ID도 검사했다. 매 회 480×480 영상 5fps를 시뮬 시간 기준으로 처리했다.

세 번째 배치에서는 마지막 상자 ID 667을 394.696초에야 읽었다. 로봇은 62초 무렵 상자에 0.82m까지 접근했지만, 그때 영상에는 마커 면이 보이지 않았다. 394.6초 프레임에는 인쇄된 면이 정면으로 나타났다. 이 사례는 **가까이 갔다는 이유만으로 상자 면을 관찰 완료 처리해서는 안 된다**는 반례다. 해당 면을 뒤늦게 확인했기 때문에 실제 완주 시간은 396초로 늘었다.

## 한계와 다음 진단

다섯 배치 모두 성공했지만 표본 수가 적고, 같은 월드에서 직전판과 쌍으로 비교한 것은 첫 배치뿐이다. 두 번째 배치에서는 작은 후보 목표를 선택한 뒤 상자 마커가 등록되어, 약한 흑백 단서를 벽 전용 증거로 해석해서는 안 된다. 실제 OAK-D 노출, USB/DDS 전송량과 Create3 부하도 Gazebo 결과만으로 검증되지 않는다. 다음 개선은 세 번째 배치처럼 가까이 지나쳤으나 카메라로 인쇄면을 보지 못한 상자를 더 이른 시점에 재방문할 수 있는지, 다른 배치의 벽 탐색 시간을 늘리지 않고 비교하는 것이다.

8780 보드는 새 무작위 배치가 상자 3개·5개가 아니면 완료 후 보관함으로 옮기고, 3개 마커 주행도 예전 2개짜리 `pair_time_s` 기준 때문에 `일부 미달`로 표시했다. 실험 목록에서 상자 수가 달라도 고정 책상·상자형 장애물·마커 3개인 배치를 표시하고, 상세 완료 판정에는 원본 `exam-score.json`을 사용하도록 보드 코드를 고쳤다. ㄱ자 장애물이 있는 네 번째 스트레스 배치는 현재 목록에 수동 복원해 두었다. 다섯 기록의 API와 상세 화면 모두 3/3 완주로 표시되는 것을 확인했다.
