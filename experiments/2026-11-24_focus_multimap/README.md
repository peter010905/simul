# Focus Continuity 주행 비교 · ROS 2 Jazzy

원본은 실물 보드에서 `start-focus`를 누를 때 선택하는 `v152_focus_continuity_box1122_ws`다. 이번 시험은 Jazzy VM의 Gazebo에서 같은 프로그램을 실행한다. 비교 대상 모두에게 640×480·5fps RGB 입력을 주며, 검출기에서 사용하는 보정값은 시뮬레이션 CameraInfo에서 얻는다.

## 시험 조건과 성공 기준

시험장과 책상은 고정한다. 맵마다 출발 자세, 상자, 마커의 위치와 ID를 바꾼다. 같은 시드에서는 정책 간 월드 해시와 시작 자세를 대조한다. 정책이 미리 아는 마커 수는 3개다. 제한 시간은 시뮬레이션 600초다. 정답 위치와 ID는 평가기에만 사용한다. 최종 통과에는 세 ID의 올바른 등록, 등록 후 실제 1.5m 접근, 로봇의 근접 영상 증거, 저장 위치 오차 25cm 이내, 오등록과 범퍼 접촉 0회가 모두 필요하다.

`prior_slam_map`이 있는 회차는 별도 시험이다. 같은 월드·배치·출발 자세에서 이전 주행이 저장한 SLAM Toolbox의 posegraph와 data 파일을 사용한다. 새 미션의 마커 목록과 RGB 관찰 이력은 빈 상태에서 시작한다. 정답 지도를 사전에 제공하지 않는다.

## 어떤 동작을 비교하는가

| 버전 | 주요 변경 |
| --- | --- |
| .1 Focus Continuity | 원본의 동일 ID 집중 재관찰, 상자 면 탐색, 진입점과 동작을 유지한 카메라 대조군 |
| .18 Finish Transit | 일반적인 주기 회전 때문에 안전하게 진행 중인 경로가 끊기는 현상 수정 |
| .19 Calibrated Routes | 카메라 초점거리와 지도 좌표가 바뀌는 오류, 경로 비용 단위, 연결 격자 계산 지연 수정 |
| .20 Wall Evidence | 일반 벽의 예상 관찰 거리를 실제 RGB 완료 판정과 일치시킴 |
| .21 Bearing Advance | 거리 없이 반복 판독된 ID 쪽으로 지도·비용지도에서 안전한 짧은 재관찰 이동 허용 |
| .22 Surface Service | 확인할 상자 면을 가까운 구역에서 묶고, 실제로 새 벽 구간을 본 방향을 기억해 벽 관찰 예약에 반영 |
| .23 Local Print Route | 익명 흑백 후보의 2.4m 이탈 예산에 실제 미터 단위와 두 지도 제약을 모두 적용 |
| .24 Observe Here | 단일 벽 면을 현재 자리에서 안전하게 촬영할 수 있을 때 짧은 이동을 기존 Nav2 관찰 회전으로 대체 |
| .25 Partial Face | 확인된 상자 앞에 짧은 미관측 띠가 있을 때, 알려진 자유 공간에서 그 경계에 카메라를 향하는 짧은 접근을 선택지에 포함 |

모든 개선판은 원본에서 별도로 설치할 수 있다. 범퍼 복구, Nav2 충돌 검사, 확정 ID의 근접 증거 판정은 계속 사용한다. 각 후보 디렉터리의 설치기가 필요한 소스·설정 해시와 부모 버전을 검증한다.

## 결과 읽기

- `exam-score.json`에는 마커별 등록, 1.5m 이내 실제 접근, 센서로 확인한 시각이 따로 있다. 세 지표 중 하나만 성립해도 완료로 세지 않는다.
- `behavior.json`은 촬영 시각·카메라 보정·기체 자세로부터 표면이 충분히 보였을 기회를 따로 계산한다. 샘플은 폭 20cm의 가상 마커를 가정하고 가림을 확인한다. 실제 ID의 판독·성공은 위의 독립 채점 항목이다. 조기 종료된 회차끼리 전체 표면 비율을 비교할 때는 서로 다른 촬영 시간을 감안한다.
- `repeated_no_new_view_m`는 이전 14~85초 사이에 지나간 경로를 다시 지나며 새로 볼 수 있는 표면이 없었던 거리를 재는 지표다. 꼭 필요한 통로 통과도 포함할 수 있다. `turns_at_rest_s`와 `almost_still_s`는 기체 자세 변화에서 계산한 값이며 각 구간의 원인은 행동 로그와 함께 확인한다.
- `compare.py ARCHIVE`는 완료 증빙이 있는 행만 CSV로 출력한다. 종료 시각과 전부 확인한 시각을 구분하며, 센서 기록을 온전히 대조할 수 없는 항목은 빈칸으로 둔다. `mission.mp4`, `headings.csv`, `native/center_wall.jsonl`에서 실제 영상, 궤적, 목표 선택을 대조할 수 있다.
- 보드에서 취합하는 파일은 Mac의 이번 시험 폴더에 저장된다. 각 회차 이름은 `run버전-시드`, 저장된 지도를 이용한 회차에는 `-prior`가 붙는다. 같은 맵에서 한 번 성공한 사실만으로 기본 정책을 교체하지 않는다.
- `turn_reversals`는 궤적에서 기체가 좌우로 연이어 방향을 바꾼 횟수다. 약 0.25초 간격에서 각각 0.15rad/s 이상, 15° 이상 회전하고 반대 방향 회전이 1.5초 이내에 시작한 경우를 센다. 필요한 마커 관찰 회전도 포함되므로 각 사건은 `turn_reversals.py ARCHIVE`가 출력하는 시각에서 영상 및 목표 로그와 대조한다.

## 확인한 원인과 행동 기준

- 원본 실행 경로와 노드 간 역할은 [Stable Survey 분석](../../policy_candidates/2026-11-24_v152_stable_survey/README.md)에 있다. 카메라는 5Hz, Nav2 제어기는 20Hz로 동작한다. 진행 중인 이동은 Nav2가 소유하고 접촉·센서 장애는 일반 관찰보다 먼저 처리한다. 취소한 목표의 늦은 응답은 새 목표를 바꾸지 못한다.
- `WallBearings.choose`에서 카메라 초점거리를 관찰자 지도 좌표로 덮어썼다. 두 번째 후보부터 거리 추정이 로봇이 서 있는 지도 좌표에 따라 달라졌다. [보정 수정과 격자 경로 회귀 검증](../../policy_candidates/2026-11-24_v152_calibrated_routes/README.md)
- `PrintMemory.choose`는 미터 단위 경로에 격자 해상도를 다시 곱했다. 5cm 격자에서 4m를 0.2m로 처리할 수 있었다. 짧은 이탈의 2.4m 예산을 두 지도의 공통 안전 경로에 적용했다. [익명 후보 우회 수정](../../policy_candidates/2026-11-24_v152_local_print_route/README.md)
- 일반 벽 관찰점은 정면 2.95m까지 생성됐지만 같은 보정에서 벽을 확인했다고 기록할 수 있는 정면 한계는 1.676m였다. 두 계산을 일치시켰다. 이 수치는 해당 시뮬 카메라의 벽 관찰 한계다. 먼 마커 후보, ID 판독, 1.5m 이내 접근 증거는 따로 처리한다. [벽 관찰 범위](../../policy_candidates/2026-11-24_v152_wall_evidence/README.md)
- 상자의 보이는 미확인 면은 반경 2.2m 안에서 최대 4개 목표 또는 55초까지 이어 본다. 실제 RGB·LiDAR 증거를 쌓은 면만 완료다. 길이 막혔거나 시간 한도에 도달한 면은 미확인으로 남고, 다른 구역으로 향하는 길이 옛 구역을 지나도 통과를 허용한다. 상자를 돌다 새 벽 구간을 촬영하면 해당 벽의 기록도 갱신한다. [구역과 벽의 목표 선택](../../policy_candidates/2026-11-24_v152_surface_service/README.md)
- 같은 ID를 반복해서 읽고도 거리값이 없어 접근하지 못한 실례가 있었다. 지도에서 연결된 짧은 이동으로 다시 시야를 확보하며 방향 단서로 ID 등록이나 접근 성공을 기록하지 않는다. [거리 없는 ID 처리](../../policy_candidates/2026-11-24_v152_bearing_advance/README.md)

## 동일한 배치에서 관찰된 차이

시드 550866253에서 상자 세 개, 북쪽 벽의 마커 한 개와 서로 다른 상자에 붙은 마커 두 개를 사용했다. 아래는 정책별 한 회차다. “재통과”는 최근 궤적을 되밟으며 새 카메라 관찰 기회가 없었던 거리다.

| 정책과 출발 지도 | 근접 확인 | 시간 | 주행 | 정지 중 회전 | 재통과 | 범퍼 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 원본 .1, 빈 지도 | 3/3 | 457.5초 | 74.9m | 87.0초 | 0m | 0 |
| .18, 빈 지도 | 1/3 | 600초 제한 | 54.9m | 208.25초 | 기록 부족 | 0 |
| .20, 빈 지도 | 2/3 | 600초 제한 | 67.8m | 171.75초 | 3.25m | 0 |
| .21, 빈 지도 | 3/3 | 554.4초 | 68.4m | 142.0초 | 1m | 0 |
| .22, 빈 지도 | 3/3 | 358.7초 | 54.2m | 72.75초 | 2.5m | 0 |
| .22, 저장 SLAM 지도 | 3/3 | 258.1초 | 39.8m | 61.0초 | 0m | 0 |

빈 지도에서 .22의 북쪽 벽 관찰 기회는 원본 65.1%에서 81.4%로 늘었고, 서쪽은 약 46%에서 31%로 줄었다. 전체 벽은 68.4%에서 66.5%, 상자 표면은 두 회차 모두 75.6%였다. 마커 세 개를 찾으면 미션을 끝내므로 전체 커버리지는 종료 시점의 값이다. 이 맵에서는 시간을 단축했지만 모든 벽의 누락과 재통과를 줄였다고 할 수 없다. 두 회차의 연속 좌우 전환은 14회와 13회였다.

저장 지도 회차는 앞선 .21의 SLAM posegraph와 data를 실제로 로드했다. 초반 약 5초에 알려진 격자는 빈 지도 3,775셀, 저장 지도 91,245셀이었다. 마커 목록은 빈 상태로 출발했고 세 마커에서 모두 새로운 근접 증거를 얻었다.

실물 로그의 동일 SLAM 스냅숏 32개에서 목표 선택 계산의 중앙값과 95백분위는 원본 437/556ms, .22는 185/239ms였다. 센서 노출부터 바퀴 응답까지 걸리는 실물 지연은 별도로 측정해야 한다. 저장 지도 시험을 포함해 시드 550866253의 실험 마커는 벽 25cm, 상자 20cm다. 10cm 실물 마커의 탐지 거리는 이 결과에서 직접 구할 수 없다.
