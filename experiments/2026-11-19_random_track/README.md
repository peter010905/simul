# 트랙 월드의 무작위 마커 탐색

비교 대시보드의 **새 랜덤 트랙 주행**에서 기본 선택인 원본 R32 + 최신 Mixed를 누르면 같은 배치에서 Gazebo 두 대가 동시에 시작한다. Mixed와 기존 Flow v3는 단독 실행도 가능하다. 매번 임의 시드를 뽑고 트랙, 창문, 기둥, 책상은 고정한다. 파란 상자 네 개와 로봇 출발 위치는 매번 달라진다. Original 마커 7·32·103의 부착 대상을 섞어 벽 한 면과 서로 다른 상자 두 개에 하나씩 붙인다. 마커를 붙일 면은 출발 위치에서 가려지고 관찰 위치까지 연결되는 후보에서 고른다. 상자가 책상 상판의 수직 투영 영역에 들어가는 배치는 다시 뽑는다.

각 회차의 실제 배치와 시드는 출력 디렉터리의 `scene.json`, 거리·판정은 `metrics.json`, 전방 카메라 영상은 종료 후 `mission.mp4`에 저장한다. 600초는 시뮬레이션 시간 기준이다. 성공은 세 ID 각각의 등록과 등록 후 1.5m 이내 실제 접근을 요구한다. 시뮬레이터와 관측기만 마커의 정답 좌표에 접근한다.

VM의 `~/track-experiments/2026-11-19_random_track/run.sh mixed`도 같은 생성기와 녹화를 사용한다. 이 경로는 ROS 2 Jazzy, 설치된 정책 작업공간, 인접한 복도 실험 및 마커 쌍 실험의 계측 코드를 사용한다. Mixed·Flow 단독 및 동시 실행의 Mixed는 ROS 도메인 174, 동시 실행의 R32는 175를 사용한다. 둘 다 VM 루프백에서 작동한다. 원본 월드 생성기는 별도 설치한다. 기준 버전은 yeonslay/turtlebot4-marker-slam의 `73bbb05`이다. 기본 참조 루트 `~/track-reference-73bbb05` 안에 `resources/demo_boxes_walls.yaml`과 원본 `src`를 가리키는 `osp_project` 패키지를 둔다.

24개의 서로 다른 시드에서 모두 벽 한 면·상자 두 개 조건과 책상 겹침 검사를 통과했다. 첫 Mixed 실행의 시드는 3416493641이다. 서쪽 벽에는 103번, 서로 다른 두 상자에는 7번과 32번이 붙었다. 출발 승인, Gazebo 위치 변화, 전방 영상 수신을 확인했다.


## 원본 R32와 Mixed 동시 주행

VM에서 `run.sh pair`를 실행하면 월드를 한 번 생성하고 두 주행이 같은 월드·시작 자세·마커 좌표를 읽는다. 각 주행의 카메라와 판정 로그는 별도 폴더에 기록된다. 원본 R32는 `73bbb05`의 `mission_r32_hardware.yaml`에 시뮬레이션 시간을 적용한다. 준비된 작업공간은 `~/r32_upstream_73bbb05_ws`다.

시드 3768776676에서 두 마커는 서로 다른 상자(7, 103), 한 마커는 북쪽 벽(32)에 붙었다. R32는 초반 0.8m 이동 후 전역 장애물 지도의 수신 간격이 실시간 3초를 넘겨 목표를 반복 취소했다. 지도 갱신과 발행을 1Hz에서 4Hz로 바꾼 뒤 정체 위치에서 2.45m 이탈했다. 이후 동시 트랙에서는 출발 전에 같은 설정을 적용한다. 이 변경은 장애물·범퍼 판정 기준을 바꾸지 않는다.

두 시뮬의 물리 계산 간격을 실행 도중 1ms에서 4ms로 변경했다. 이후 트랙은 4ms로 시작한다. 카메라 100프레임 간격으로 계산한 배율은 Mixed 0.20→0.33, R32 0.21→0.32였다. 주행 중에 설정이 달라진 이 회차의 시간은 초기부터 동일한 조건으로 진행한 성능 시험과 구분한다.
