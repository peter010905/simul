# 복도 옆 벽과 상자 뒷면 마커 주행 비교

같은 Gazebo 장면에서 기존 Flow v3와 Mixed를 세 번씩 주행했다. 7번은 왼쪽 벽에, 103번은 출발 위치에서 보이지 않는 상자 뒷면에 붙였다. 두 마커는 Original 사전의 14cm 마커다. 출발 자세와 월드 파일은 여섯 회차 모두 같았다.

등록된 ID마다 로봇 중심이 마커 중심에서 수평거리 1.5m 이내에 진입한 시각을 Gazebo 실제 위치로 확인했다. 완료 조건은 두 ID 모두 등록과 접근을 충족하는 것이다. 제한은 시뮬레이션 120초였다. 범퍼는 접촉 신호가 새로 발생한 횟수다.

| 주행 | 최종 등록 ID | 7 등록 후 접근 (초) | 103 등록 후 접근 (초) | 종료 (시뮬 초) | 실제 경과 (초) | 범퍼 |
|---|---|---:|---:|---:|---:|---:|
| flow-1 | 103 | — | 114.42 | 120.00 | 154.4 | 0 |
| flow-2 | 103 | — | 55.93 | 120.00 | 242.9 | 0 |
| flow-3 | 103 | — | 77.11 | 120.00 | 250.6 | 0 |
| mixed-1 | 7, 103 | 21.14 | 79.35 | 79.35 | 161.5 | 0 |
| mixed-2 | 103 | — | 55.55 | 120.00 | 319.2 | 0 |
| mixed-3 | 7, 103 | 23.37 | 79.80 | 79.79 | 203.7 | 0 |

Flow 1회차 7번은 전방 RGB 영상 600장 중 1장에서만 사후 판독됐고, 그때 마커 중심은 화면 왼쪽에서 너비의 5.1% 지점에 있었다. Mixed 1회차는 7번을 63장에서 판독했고 두 마커 등록·접근을 79.35초에 달성했다. 같은 고정 장면을 반복한 결과이므로 새 방이나 실물 성공률은 별도 시험이 필요하다.

영상은 매 회차 카메라 프레임을 시뮬레이션 시간 기준 5fps H.264로 저장했다. 각 파일의 길이, 프레임 수, SHA-256, 개별 마커 최소 거리와 첫 등록 시각은 [결과 JSON](results.json)에 있다. 비교 보드에서 각 주행 카드를 열면 지도와 영상을 볼 수 있다.

VM에서 재현하려면 이 폴더와 인접한 2026-11-19_pair_7_103 폴더를 함께 두고, 새 출력 경로로 아래 명령을 실행한다. 두 정책은 같은 센서와 Flow v3 설정을 사용한다.

```bash
./run.sh flow /tmp/new-flow-trial
python3 finish_trial.py . /tmp/new-flow-trial
./run.sh mixed /tmp/new-mixed-trial
python3 finish_trial.py . /tmp/new-mixed-trial
```
