# 화면 가장자리와 흐린 인쇄 테두리 재관찰

11월 18일 Flow v3 녹화 4개의 동기화된 영상 11,600프레임을 재생했다. 두 실패 구간의 원본을 먼저 확인하고 단서 검출과 같은 면 연결을 수정했다. 주행 경로는 녹화된 것을 따르며, 실물 구동기는 호출하지 않는다.

## 두 장면의 원인

- **17:23, 7번.** 로봇이 회전하면서 표식이 화면 오른쪽에서 들어온다. 미션 201.172초에는 표식 일부가 잘려 이진 외곽선에 꼭짓점이 8~10개였다. 201.274초에는 네 꼭짓점이 잡혔고 흰 여백과 검은 테두리 밝기 차이가 약 116이었지만, 가장 오른쪽 꼭짓점이 250픽셀 영상의 x=248이라 기존 4픽셀 여백 조건에서 탈락했다. 부분 검출을 회복한 뒤에도 두 라이다 반사점의 평면 위치는 1.4cm 차이인데 국소 법선 방향이 약 51도 달라 두 관측이 분리됐다.
- **17:43, 103번.** 표식이 이미 전부 보이는 동안에도 영상에서 테두리가 번져 내부 무늬와 이어졌다. 61.488·61.693·61.889초에 기존 적응형 이진화 외곽선은 9·8·9개 꼭짓점으로 나왔다. 기존 규칙은 61.991초에 사각형 하나를 잡았지만 62.090초에는 다시 놓쳤고, 두 번 확인하기 전에 62.192초에 ID가 읽혔다.

## 수정

화면 좌우 경계에서 잘린 표식은 실제 화소가 보이는 세 변의 안팎 대비와 내부의 양방향 무늬를 확인해 추적을 시작한다. 가장자리 밖의 추정 화소는 밝기·무늬 판단에서 제외한다. 재관찰 동작은 다음 관측에서 중심과 화면 끝 사이에 예상 최소 변의 절반 이상 여유가 있을 때만 허용한다. 흐린 테두리는 원 외곽선의 볼록 껍질에서 네 꼭짓점을 복원한 뒤 원본 영상의 흰 여백·어두운 띠·내부 패턴 검사를 다시 거친다.

같은 방위에 다른 깊이의 반사가 섞이면 면 연결을 거부한다. 한 면으로 볼 근거가 있는 인접 라이다 점 4개 이상이 10cm 이상 이어지면 국소 선분을 맞춰 방향과 관측점을 안정화한다. 잔차가 2.2cm를 넘거나 보정량이 6.5cm를 넘으면 기존 단일점 추정을 사용한다. ID 판독기, 18픽셀 판독 기준, 두 프레임 조건과 사후 위치 비교 기준은 기존과 동일하다.

## 같은 네 로그의 비교

기준은 고정 영상의 첫 18픽셀 ID 판독보다 먼저 선택했는지, 선택한 면이 기록된 마커 위치 30cm 이내이고 관찰자 쪽을 향하는지다. 17:08은 원래 마커 좌표가 없어서 이전 평가와 동일하게 영상 판독 방향과 라이다로 추정한 위치를 사용했다.

| 주행·ID | 기존 첫 선택과 영상 판독의 차이 | 개선판 첫 선택과 영상 판독의 차이 | 선택한 곳과 마커 좌표의 거리 |
|---|---|---|---:|
| 17:08 · 103 | 0.40초 전 | 1.10초 전, 시선 유지 | 11.1cm (추정 기준점) |
| 17:23 · 7 | 판독 전 선택 없음 | 0.10초 전, 우회전 제안 | 6.1cm |
| 17:37 · 7 | 0.10초 후 | 7.50초 전, 우회전 제안 | 17.4cm |
| 17:43 · 103 | 판독 전 선택 없음 | 0.80초 전, 영상에서 마커 방향으로 우회전 제안 | 49.8cm |

같은 30cm 기준으로 1/4회에서 3/4회가 됐다. 17:43 첫 선택은 61.388초, 첫 판독은 62.192초였다. 영상에서 올바른 인쇄물을 가리켰지만 기록 좌표와의 차이가 커서 위치 일치에 포함하지 않았다. 61.991초에 기록 좌표 근처의 반복 단서가 생겼지만 추가 회전은 선택되지 않았다. 전체 즉시 재관찰 제안은 6회에서 5회가 됐다. 비교 영상은 0.5배속이고 표시된 초는 원래 미션 시각이다. 이번 두 실패 영상을 보고 조건을 조정했으므로 다른 주행에서의 개선율은 별도 검증이 필요하다.

## 재현

ROS 2 Jazzy의 Flow v3 surface sweep 환경에서 아래 명령을 실행한다. BASELINE_DIR에는 면 기억 방식의 주행별 JSON을 둔다. RUNS에는 네 원본 주행 폴더를 시간순으로 전달한다.

```sh
python3 replay_recovery.py BASELINE_DIR OUTPUT_DIR RUNS...
python3 -m unittest -v test_recovery test_square_face test_surface_memory
```

카메라·라이다·자세를 시간순으로 읽고, ID와 기록 위치는 사후 대조에만 쓴다. results.json은 동기화 프레임 수, 선택 횟수, 첫 판독 시점, 위치 일치 여부를 담는다. 실제 구동 시 발견 시간이 얼마나 달라지는지, 다른 장소에서도 잘 동작하는지는 이 재생에서 측정하지 않았다.
