Mixed v1.4.0은 장애물이 많은 곳에서 실패 이력이 쌓여 후보를 소진하거나, 같은 자리에서 목표만 바꾸는 문제를 줄이기 위한 별도 실험판이다. v1.2와 v1.3.1 작업 공간 및 기존 보드 버튼을 보존한다. 새 작업 공간은 `flow_v3_r32_crowded_ws`, 실물 보드 버튼은 `Mixed · 밀집 장애물 판단 (v1.4 실험 · 0.30 m/s)`이다.

현재 코드에서 확인한 문제와 변경은 다음과 같다. 최근 실물 로그를 튜닝 입력으로 쓰지 않았다.

| 코드 위치 | 기존 동작과 문제 조건 | v1.4의 변경 |
| --- | --- | --- |
| `mission.py: accepted, completed` | 거부·실패·범퍼 취소 목적지도 `excluded`에 넣는다. 이 목록이 방문 페널티와 최근 목표 반경 거부에 함께 쓰여, 가지 못한 위치 주변도 방문한 것처럼 후보가 줄어든다. | 성공한 목표만 방문 이력에 넣는다. 실패한 목표는 기존 odom 좌표 기준 60초 쿨다운으로 관리한다. |
| `center_wall.py: dispatched, attempts` | 출발할 때 면 관찰 시도를 소비한다. 실제 도착하지 못해도 두 번 시도한 면은 오래 제외된다. | Nav2 결과와 연결한다. 실패한 시도는 45초 뒤 시도 예산에서 빠진다. 센서 중단 뒤 같은 목표를 재개해 성공하면 정상 성공 기록으로 남긴다. 실제 RGB 관찰 완료 판정은 별도다. |
| `phased_hybrid.py: select`, 새 `CommonRoutes` | 목적지가 SLAM과 Nav2 지도에서 각각 연결됐는지 검사해도, 두 지도가 허용하는 통로가 다르면 공통 경로는 없을 수 있다. | 좌표계·원점 회전·해상도를 맞춘 공통 통행 그래프에서 경로가 있는 후보를 선택한다. 마지막 목표 전송 직전에도 검사한다. |
| 새 `CrowdedFlow`와 `mission.py: tick` | 목표를 새로 보낼 때 무진행 타이머가 초기화된다. 후보 소진 시에는 관찰 회전과 후진 시도가 반복될 수 있다. | 45초 이내 같은 반경 0.5m에서 두 번 실패하면 목표 간 실패 상태를 유지하고 가까운 우회 관측점을 우선한다. odom에서 0.4m 이동해야 이 상태가 해제된다. |

우회 관측점은 현재 위치에서 직선거리 0.45~1.0m, 공통 그래프의 경로 길이 0.45~1.6m인 후보에서 고른다. 여유 공간, 주변의 열린 공간 비율과 회전량을 평가한다. 최근 90초의 실제 odom 궤적과 이미 보낸 우회점에는 방문 페널티를 준다. 현재 선택된 탐색 방향을 약하게 선호하되, 실패 방향의 반대쪽을 무조건 선호하지 않는다. 새 우회 목표에는 면 관찰·마커 접근 완료 점수를 주지 않는다. 확인된 마커를 현재 위치에서 관찰하는 동작은 우회보다 우선한다.

후보와 우회점이 모두 없으면 같은 위치에서 추가하는 탐색 회전을 한 번, 60도로 제한하고 2초 간격으로 재계산한다. 기존 마커·표면 증거에 따른 관찰 회전은 유지한다. 대시보드 `navigation_flow`에는 `planning_reason`, `common_reachable_cells`, `common_route_rejections`, `crowded_escape_pending`을 보낸다. 비용지도가 없거나 3초 넘게 오래됐으면 `waiting_for_shared_costmap`으로 대기한다.

목적지의 SLAM 장애물 여유 0.32m, Nav2의 알려진 통행 비용 `<99`, 기존 footprint·inflation·collision monitor와 범퍼·낭떠러지·스톨 정지는 유지한다. 기존 시작 위치 예외를 사용해도 원본 지도나 센서 데이터를 수정하지 않고 Nav2 차단 셀을 열지 않는다. 실제 이동은 기존 Nav2 Action으로 실행한다. 공통 그래프는 후보를 거르는 검사이며, 실제 Global Planner의 경로 성공이나 실물 통과를 보증하지 않는다.

격리 검사에서는 새 지도·상태전이 검사 28개를 포함해 안전 복구·속도·센서·마커 검사 62개와 보드·세션 검사 74개가 통과했다. 기존 `test_actual_mission_tick_does_not_interrupt_transit_for_a_wall_glance`는 v1.3.1에서도 실패해 분리했다. 모의 객체에 현재 런타임이 요구하는 `inspectable_route`가 없다. 예전 center-first의 시간 예약 테스트도 원본에서 같은 기대값 불일치가 발생한다. 이 두 결과를 새 수정의 통과로 계산하지 않았다.

[합성 비교 결과](synthetic_results.json)에서 실패 세 번이 방문 이력에 남는 수는 기존 3개에서 0개로, 도달하지 못한 면의 시도가 80초 후에도 남는 수는 2회에서 0회로 바뀌었다. 서로 다른 통로를 허용하는 두 지도 반례에서 기존 개별 연결 검사는 모두 통과했지만 새 판은 해당 목표를 거부하고 공통 통로 안의 대체점을 찾았다. 300×400 셀 지도에서 공통 그래프를 추가 계산하는 시간은 Gazebo 실행 중 12회 기준 중앙값 약 94ms, 95백분위 약 99ms였다. 전체 미션 계산시간은 별도다.

새로 만든 동일 U자 막다른 길·밀집 상자 장면에서 기존판과 수정판을 각각 90초씩 순차 실행했다. [전체 비교](gazebo_comparison.json)는 제외한 중간 수정판도 포함한다.

| 실행판 | odom 이동 거리 | 정지 시간 | 무진행 취소 | 범퍼 접촉 | 판독 ID |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기존 v1.3.1 | 0.96m | 14.48초 | 4 | 0 | 0 |
| 우회 방향을 반대로 편향한 초기판, 제외 | 0.77m | 32.06초 | 5 | 0 | 0 |
| 최종 v1.4, 실제 궤적·열린 공간 반영 | 0.95m | 16.21초 | 4 | 0 | 0 |
| 별도 사전 정렬을 추가한 판, 제외 | 1.00m | 42.50초 | 5 | 0 | 0 |

최종판의 이 장면 탈출 성능이 좋아졌다는 근거는 없다. 반복 실패 뒤 우회점을 선택하고 기존 주행·면 관찰 목표로 복귀하는 동작은 확인했지만 무진행 취소가 남았다. 정지 시간은 odom 전진 속도 절댓값 0.015m/s 미만이면서 회전 속도 절댓값 0.06rad/s 미만인 구간이며, 나머지 대부분은 제자리 회전이었다. 주행 기한 이후 저장하는 짧은 구간도 측정에 포함된다. 세 마커를 찾는 10분 완주 시험이나 여러 맵의 평균 성능 비교로 해석하면 안 된다.

시험은 실물 도메인 4와 분리한 도메인 182, 동일한 기존 Cyclone DDS localhost 설정에서 수행했다. 초기 Fast DDS 실행들은 SLAM 준비를 통과하지 못해 비교에서 제외했다. MPPI 전진·회전 상한은 0.30m/s·0.50rad/s이며, 시뮬레이션의 기존 smoother/behavior 회전 상한 0.75rad/s와 실물의 0.50rad/s 설정은 각각 보존했다. 원본 Nav2 경로의 발행은 확인했으나, 이동 진척이 막히는 최종 원인은 명령·제어 단계의 추가 계측이 필요하다.

설치는 준비된 v1.3.1 소스 해시를 검사하고 새 디렉터리에만 복제한다. 기존 디렉터리가 있으면 중단한다.

```sh
source /opt/ros/jazzy/setup.bash
candidate="$PWD/policy_candidates/2026-11-20_mixed_crowded_navigation"
python3 "$candidate/install.py" ~/flow_v3_r32_smooth030_ws ~/flow_v3_r32_crowded_ws
cd ~/flow_v3_r32_crowded_ws
colcon build --symlink-install --packages-select osp_mission
source install/setup.bash
ROS_DOMAIN_ID=183 ROS_LOCALHOST_ONLY=1 python3 -m pytest -q "$candidate/test_crowded_navigation.py"
```

실물 주행은 이번 작업에서 시작하지 않았다. 밀집 구간의 실제 탈출률·충돌률과 10분 마커 탐색 성능은 추가 비교가 필요하다.
