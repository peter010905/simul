# Mixed v1.3.0 · 막힘·스톨 복구

v1.2 마커 재관찰판에서 분리한 실험 버전이다. 실물 보드의 **Mixed · 막힘·스톨 복구 (v1.3 · 0.45 m/s)** 버튼은 `flow_v3_r32_stall_recovery_ws`와 `--forward-045 --recover-stall`을 선택한다. v1.2 버튼과 작업 공간도 계속 사용할 수 있다.

## 확인한 원인과 변경

18시 03분과 18시 07분의 실물 주행에서 정지 감지가 각각 네 번, 세 번 발생했다. `navigation_stalled` 취소 결과가 목표 제외와 새 목표 선택으로만 이어져 후진 복구가 예약되지 않았다. 첫 정지 시점에는 두 회차 모두 기존 후방 스캔 검사를 통과했다. v1.3은 주행 정체 취소, 시간 초과, Nav2의 실제 목표 실패 후 기존 안전 후진을 검토하고 재계획한다. 후진은 같은 20cm·0.08m/s, 후방 스캔 검사, Nav2 충돌 검사, 재시도 간격과 실패 대기시간을 적용한다. 관찰·센서·새 마커 때문에 취소한 이동은 해당 원래 처리로 이어진다. 일반 목표 실패 후에도 안전 후진이 추가되므로 불필요한 실패 목표가 많은 장면에서는 시간이 더 들 수 있다.

실물 로봇이 발행한 STALL=3은 바퀴가 구동 명령만큼 움직이지 못했다는 신호다. 17시 27분 회차에는 오른쪽 바퀴의 신호가 약 0.368초 뒤 해제된 구간이 있었다. 이후 기록에는 CLIFF=2도 등장한다. 장애물 접촉, 탑재 부하, 바닥 조건, 로봇을 들어 올린 동작, 순간 오검출 중 실제 원인은 이 기록만으로 확정할 수 없다.

v1.3에서는 스톨 신호 수신 즉시 속도를 0으로 보내고 현재 동작을 취소한다. 신호가 해제된 상태가 1초 이상 이어지고, 신선한 위험·바퀴 오도메트리와 0.5초 이상의 정지가 확인돼야 후진·재계획을 검토한다. 위험 데이터가 끊기면 정지를 유지한다. 스톨이 2초 이상 이어지거나 낭떠러지·바퀴 들림이 감지되면 실행을 종료한다. `--recover-stall`은 새 작업 공간에서 명시적으로 선택하며 기존 실행의 스톨 종료 처리는 유지된다.

## 원본 기록 비교

| 실물 녹화 | 정지 취소 | v1.2 복구 예약 | v1.3 복구 예약 | 당시 스캔이 후진을 허용한 정지 상태 |
| --- | ---: | ---: | ---: | ---: |
| 18시 03분 | 4 | 0 | 4 | 4 |
| 18시 07분 | 3 | 0 | 3 | 1 |

같은 기록의 실제 `Mission.completed` 호출과 저장 스캔을 비교한 결과이다. 두 회차의 첫 정지 상태에서 후진 검사가 통과했다. 이후 경로는 후진으로 바뀌므로 일곱 상태를 새 주행의 연속 결과로 해석할 수 없다. 실물 탈출 성공률, 충돌 횟수, 완주 시간은 v1.3으로 아직 측정하지 않았다. JSON 결과는 `results.json`에 있다.

새 정지·스톨 상태 전이, 후방 장애물, 후진 실패 대기, 기존 마커와 최종 속도 설정을 검사한 19개 테스트 및 보드·세션 검사 64개가 통과했다. 추가로 확인한 기존 `test_recovery.py`·`test_navigation_flow.py`의 일곱 실패는 v1.2에도 동일하게 존재한다. 여섯 개는 현재 초기 상태의 `cancel_reason` 등이 빠진 과거 모의 객체, 한 개는 현재 이동 중 관찰 선택과 다른 기대값에 해당한다. 이 작업에서는 해당 기존 테스트를 수정하지 않았다.

## 설치와 재현

ROS 2 Jazzy VM에서 저장소 루트를 기준으로 실행한다.

```sh
source /opt/ros/jazzy/setup.bash
candidate="$PWD/policy_candidates/2026-11-20_mixed_stall_recovery"
python3 "$candidate/install.py" ~/flow_v3_r32_marker_relook_ws ~/flow_v3_r32_stall_recovery_ws
cd ~/flow_v3_r32_stall_recovery_ws
colcon build --packages-select osp_mission
source install/setup.bash
```

별도 로컬 ROS 도메인에서 `inspect_recorded_stalls.py`는 원본 녹화의 정지 시각·실제 이동량·후방 스캔을 조사한다. `replay_recovery.py`는 그 JSON과 원본 기록 경로를 받아 현재 로드한 버전의 취소 결과 처리를 실행한다. `inspect_hardware_hazards.py`는 위험 신호 지속 시간과 최초 유형을 조사한다. 모든 재생 도구는 로봇에 동작을 보내지 않는다.
