# Mixed · 가운데 장애물 → 벽

가운데 물체를 먼저 조사하면 마커를 더 빨리 찾는다는 가설을 시험하는 실물 보드용 후보이다. 600초 미션의 초기 설정과 관찰 목표는 다음과 같다.

1. SLAM 지도에서 현재 위치와 연결된 자유 공간에 둘러싸인 장애물 경계를 찾는다. 길이 약 30cm 이상의 물체에 대해 카메라 관찰 기록이 부족한 면을 고른다. 상자 모양이나 네 면 전체의 도달 가능성은 요구하지 않는다. 각 목표의 자유 공간 여유, 경로 연결성, 비용지도, 표면까지의 시야를 확인한다. 후보가 없으면 지도를 넓힐 기존 탐색 목표를 우선한다.
2. 시작 후 적어도 60초가 지났고 35초 동안 접근 가능한 가운데 후보가 없으면 다음 계획에서 벽 단계로 넘어간다. 접근 가능한 벽면이 있어야 벽 단계로 넘어간다. 55% 이후에는 처음 시도할 안쪽 면이 없으면 벽을 우선한다. 여전히 안쪽 후보가 남아도 관찰 가능한 벽 구간 수에 따라 마지막 12초 + 구간당 5초를 벽 탐색에 배정한다. 이 시간은 미션 길이의 15% 이내(600초에서는 최대 90초)이며 관찰 가능한 벽이 있을 때만 적용한다. 짧은 미션의 초기 대기와 후보 대기 기준은 각각 미션 길이의 22%, 13% 이내로 제한한다.
3. 외곽의 관측된 경계에서 벽으로부터 0.67~1.15m 떨어진 관찰 지점을 고른다. 직전 벽 위치와 진행 방향을 기억해 같은 방향으로 가까운 구간을 선호하고 도착하면 벽 쪽으로 36도 관찰 회전을 요청한다. 같은 면의 가까운 구간에서 45초 이내 반복을 피하고 최대 두 번 시도한다. 실제 관찰 여부는 카메라 관찰 기록이 결정한다. 지도에서 더 고를 벽이 없으면 기존 Flow 탐색 목표를 사용할 수 있다.
4. 마커 ID 확인 및 접근 목표와 위치가 잡힌 인쇄 후보를 단계 목표보다 먼저 평가한다. 단계별 선택은 실행 폴더의 `center_wall.jsonl`에 남는다. 지도에 물체 바깥쪽 통로가 아직 나타나지 않았거나 벽에 붙어 있는 물체는 외곽에 포함될 수 있다. 벽 단계는 Nav2 관찰 지점들의 순차 방문이며 두 지점 사이 실제 궤적은 Nav2가 결정한다.

## 확인 결과

- 합성 지도 검사 다섯 가지를 ROS VM에서 검증했다. 두 물체의 관찰 피드백을 이상적으로 공급한 경우 두 물체에서 각각 네 방향을 선택한 후 벽 단계로 전환했다. 한쪽만 도달 가능한 경우 그쪽 면을 선택했고, 비용지도가 차단된 경우 목표를 내지 않았다.
- 이전 실물 기록 `20261119T120017-20aecbcabc`의 결정 지도 7장 중 5장에서 안쪽 면을 선택했다. 61.2초, 75.2초, 86.8초에는 앞서 확인한 상자 중심 근처의 서로 다른 표면 좌표가 선택됐다.
- `20261119T110237-11c9096872`의 결정 지도 40장에서 안쪽 면 선택 33회, 벽면 선택 1회였고 첫 벽면 선택은 533.0초였다. 나머지 6장에서는 단계별 표면 목표가 없었다.
- `replay.py`는 저장된 주행 자세·SLAM 지도·카메라 관찰 기록과 결정 시점 이전에 수신된 최근 비용지도로 목표 선택만 재계산한다. 미션 시작 시각은 startup 로그 기준이며, 재선택 이력은 고정 지도 좌표계로 근사한다. 새 경로·영상과 마커 판독, 소요 시간, 범퍼는 실측해야 한다.

## 설치와 사용

VM에서 일반 장애물 버전을 기반으로 독립 작업공간을 만든다.

```bash
cd ~/simul/policy_candidates/2026-11-19_mixed_center_first
python3 install.py ~/flow_v3_r32_general_ws ~/flow_v3_r32_center_ws
source /opt/ros/jazzy/setup.bash
cd ~/flow_v3_r32_center_ws
colcon build --packages-select osp_mission --symlink-install
source install/setup.bash
python3 ~/simul/policy_candidates/2026-11-19_mixed_center_first/test_schedule.py
```

Mac의 `./robot.sh dry-run-center`는 명령을 출력하고 `./robot.sh check-center`는 준비 상태를 확인한다. 실물 구동은 대시보드의 **Mixed · 가운데 장애물 → 벽** 또는 `./robot.sh start-center`에서 시작한다.
