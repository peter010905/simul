# Flow v3 · R32 복도 주행과 마커 후보 접근

별도 후보용 런타임은 실물 보드에서 쓰던 Flow v3와 같은 마커 인식기, 가중치, MPPI, 충돌 감시와 복구 상태기를 사용한다. 참고한 R32는 2026년 11월 18일 확인한 커밋 `b1ed300e0052e147f17590f0219d8c794fb66f8a`이다. 이 버전의 복도 진행 방향 유지, 지나온 상자의 미관찰 면 선택, 연결된 비용지도 기반 우회를 사용한다. 마커 사전·ID 등록·1.5m 접근 기록 및 속도 명령의 소유자는 Flow v3 미션 하나다. [참고 버전](https://github.com/yeonslay/turtlebot4-marker-slam/tree/b1ed300e0052e147f17590f0219d8c794fb66f8a)

## 주행 중 선택

1. 범퍼·안전 복구와 센서 준비 확인이 먼저다. 확정 ID의 접근 또는 번호 단서 재관찰이 선택되면 그대로 수행한다.
2. 번호를 읽지 못한 영상에서도 인쇄 테두리를 찾는다. 화면 가장자리의 한 프레임 단서는 기존 Original 무늬 확인을 거쳐 최대 6도 짧은 시선 전환을 요청한다. 실제 주행에서는 기존 미션의 관찰 대기와 안전 회전 조건을 따른다.
3. 같은 인쇄면의 거리·방향이 서로 다른 영상에서 3회 일치하면, odom에 저장한 후보를 현재 지도에 옮긴다. 물체가 보였던 쪽에서 1.2·1.45·1.8m 떨어진 관찰 지점을 평가한다. 이미 1.5m 이내면 제자리 관찰을 검토한다. SLAM 자유 공간, Nav2 비용지도 연결, 가시선, 최근 실패 지점을 검사한다. 이동 후 카메라를 후보 쪽으로 돌려 기존 판독기가 다시 본다. 후보는 마커 ID나 과제 접근 실적에 들어가지 않는다.
4. 주행 중에는 최근 단서와 가능한 관찰 지점이 모두 있어야 평소 탐색을 중단한다. 진행 중인 ID 접근·관찰, 접촉 복구, 센서 이상 상태가 우선한다. 목적지 결정 시 비용지도를 다시 검사한다. 같은 면은 90초간 반복 요청을 제한하고 경로 중단 사이에는 20초를 둔다.
5. 일반 탐색에서 R32의 복도 전진·우회 목적지를 사용할 수 있다. 그 밖에는 Flow의 원래 선택을 사용하며 Flow에 목적지가 없을 때는 R32의 유효한 탐색 후보도 사용할 수 있다. 로컬 비용지도로 속도를 제어하는 Nav2와 행동 노드는 각각 하나다. R32가 최근 이동 경로의 상자 뒤쪽에서 보이는 미관찰 면을 찾으면 목표 방향만 기존 관찰 제어기에 넘긴다. 다시 볼 수 있는 같은 상자는 180초 동안 억제하고 상자 관찰 사이에는 25초를 둔다. 독립적인 R32 회전 노드나 마커 등록기를 띄우지 않는다.

## 설치와 선택

VM에 준비한 선택용 작업공간은 `~/flow_v3_r32_print_ws`다. Mac에서 아래 명령으로 실행 명령을 확인하거나 별도로 구동할 수 있다. 보드 기본 버튼과 기존 Flow v3 실행 경로는 유지한다.

```sh
./policy_candidates/2026-11-18_flow_v3_r32_print/robot.sh dry-run
./policy_candidates/2026-11-18_flow_v3_r32_print/robot.sh start
./robot.sh stop
```

다른 환경에서는 승인된 참고 저장소의 해당 커밋에서 `src/core.py`를 확보해야 한다. 빌더가 SHA-256을 확인한 뒤 새 작업공간을 만든다. ROS 2 Jazzy와 프로젝트의 시스템 의존성이 필요하다.

```sh
python3 policy_candidates/2026-11-18_flow_v3_r32_print/build.py ~/flow_v3_r32_print_ws --reference-core /path/to/r32/src/core.py
cd ~/flow_v3_r32_print_ws
bash build.sh
```

## 검증 범위

회귀 시험에는 새 미션의 최초 범퍼 이벤트 이전 상태, 벽으로 갈라진 비용지도, 중복 영상, 오래된 단서, ID 접근 우선권, 관찰 방향, R32 복도 경로와 막힌 끝점이 포함된다. 전체 결과는 [측정 기록](results.json)에 담았다.

실물 녹화 재생에서 17:37의 7번은 25.461초에 이동 가능한 관찰 지점이 생겼다. 지점까지 이동 거리는 0.87m, 인쇄면 추정과 주행 기록 속 마커의 오차는 0.22m였다. 첫 번호 판독은 33.061초였다. 17:23에는 면을 두 프레임만 연결했고 12:58에는 첫 판독 전 일치한 면이 없었다. 두 경우 모두 번호 판독 전 접근 제안은 없었다. 재생은 당시 영상과 비용지도에서 가능한 지점을 구했다. 새 경로에서 실제로 영상을 획득하거나 1.5m 진입을 측정한 결과는 아니다. 과거 경로 결정의 재생은 당시 지도·방문 좌표·최신 비용지도를 사용했고 저장되지 않은 일시적인 실패 상태와 전체 동작 상태는 재현하지 않았다.

최종판으로 이전 경로 결정 61건을 따로 재생했다. ID가 있는 마커 관찰 결정 1건은 원래 정책에 맡겼다. 나머지 60건에서 Flow 기본 목표가 54건, R32 복도 전진이 1건, 우회가 3건, 지나친 상자 면 관찰이 2건이었다. 이 숫자는 로봇의 실제 회전·우회 횟수와 구분한다.

재생 명령은 설치된 후보의 ROS 환경을 먼저 로드한 뒤 실행한다.

```sh
python3 replay.py /path/to/run_logs/robot
python3 replay_routes.py /path/to/run_logs/robot
```

## Gazebo 비교

같은 robust_demo 맵(seed 8000001), 시작 자세, 320픽셀 카메라, MPPI 설정, 120초 예산으로 주행했다.

| 정책 | 검출·1.5m 이내 접근 | 388번 최소 거리 | 이동 거리 | 범퍼 |
|---|---|---:|---:|---:|
| 기존 Flow v3 | 388번 1개 | 0.49m | 11.87m | 0 |
| 상자 뒷면 관찰 추가 전 | 0개 | 4.14m | 14.13m | 0 |
| 최종 합성판 | 388번 1개 | 0.52m | 13.94m | 0 |

각 시험은 시간 제한으로 종료됐다. 최종판의 388번 지도 위치 오차는 3.1cm였다. 최종 주행은 Flow 일반 목표 9개와 확인된 마커 접근 목표 1개를 실행했다. 이 시행에서 R32 상자 관찰이 발견에 기여했다는 증거는 없다. 상자 관찰은 주행 로그의 선택 재생 및 별도 복도·상자 제어 흐름 시험에서 확인했다.

초기 통합 시험에서 범퍼 접촉 이전에 상태 변수가 비어 주행 노드가 종료되는 문제를 재현해 초기화와 회귀 시험을 추가했다. 첫 Gazebo 기동 때의 DDS 통신 참가자 수 제한은 테스트 전용 루프백 설정으로 해결했다. 최종 주행에서 기존판과 합성판의 인식기 오류 카운터는 각각 14·19였으며, 양쪽에 마지막으로 기록된 오류는 영상 시각에 맞는 좌표 변환이 아직 도착하지 않은 경우였다. 확정 시각이나 위치 검증 조건을 완화하지 않았다. 실물 충돌률과 세 마커 완주율은 이번 시험으로 산출할 수 없다.
