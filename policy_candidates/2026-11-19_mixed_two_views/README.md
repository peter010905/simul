# Mixed 상자 관찰의 두 시점 확인

## 같은 무작위 맵에서의 Gazebo 실측

시드 1983050120, 회차 BVOucwt9에서 두 버전의 월드 해시와 실제 출발 위치를 대조했다. 두 개의 상자에는 32번·103번이, 북쪽 벽에는 7번이 붙었다. 두 정책 모두 범퍼 접촉 0회였다. 시간 단위는 미션 출발부터의 시뮬 초다.

| 항목 | 기존 Mixed v1 | 두 시점 Mixed v2 |
|---|---:|---:|
| 상자 마커 등록 및 1.5m 접근 | 1/2 | 2/2 |
| 32번 등록 후 1.5m 이내 | 미달 | 255.2초 |
| 103번 등록 후 1.5m 이내 | 118.7초 | 332.7초 |
| 상자 관찰 목표 수 | 11 | 10 |
| 상자 목표 발행부터 다음 목표까지의 시간 합계 | 134.5초 | 139.0초 |
| 종료 | 600.0초 시간 제한 | 332.7초 전체 성공 |

개선판의 첫 상자 접근은 136.5초 늦었지만, 이번 회차에서 두 상자를 모두 찾았다. 상자 목표에 배정된 구간은 4.5초 늘었다. 구간에는 이동과 다음 목표를 고를 때까지의 대기가 포함된다. 두 상자 완료 시간의 정확한 차이는 기존판의 미달로 측정할 수 없다. 두 정책은 다른 경로를 주행했으며 단일 시드 결과다.

32번 인쇄면 쪽에서 거리 1.5m 이내·정면 방위 오차 약 ±30°를 만족한 시간은 기존판 0.0초, 개선판 6.14초였다. RGB 영상에서 다시 읽힌 32번은 각각 0프레임과 35프레임이었다. 개선판의 자체 관측 기록에는 두 시점에서 확인한 상자 4개, 관측한 면 13개가 남았다. [전체 결과](results.json)

## 판정과 재현

비교 기준은 기존 무작위 트랙의 `mixed-box-views-v1`이다. 새 후보 `mixed-box-views-v2`는 주행 중 한 면만 보인 물체를 기억한다. 같은 물체를 25도 이상 다른 위치각에서 관측하고 두 시점의 LiDAR 반사가 서로 인접한 면 방향을 지지하면 상자로 간주한다. 모서리 끝을 지난 곳에 지도상 빈 셀이 있어야 한다. 벽에 붙은 마커와 반복된 RGB 인쇄 테두리는 기존의 별도 우선순위로 추적한다.

확인된 상자에서는 이미 카메라에 들어온 면을 제외하고, 이동 가능한 모서리 관찰 위치를 선택한다. 관측 완료에는 1.5m 이내 거리, 카메라의 실제 수평 시야와 동기화된 LiDAR 반사, 서로 다른 프레임 시각이 필요하다. 목표 발행만으로 면을 완료 처리하지 않는다. 길이 막히면 같은 면을 35초 뒤에 다시 시도할 수 있다. 등록된 마커가 있는 상자는 면 순회에서 제외한다.

- 설치는 시뮬 VM에서 `python3 stage.py ~/mixed-box-views-v1/osp_mission ~/mixed-box-views-v2`로 한다.
- 비교는 같은 VM에서 `TRACK_BASELINE_OVERLAY=~/mixed-box-views-v1 TRACK_MIXED_OVERLAY=~/mixed-box-views-v2 ./run.sh compare-mixed`로 실행한다. 무작위 맵·시작 자세·600초 예산·마커 위치를 공유하는 두 개의 Gazebo 인스턴스를 쓴다. 각 정책은 센서와 자체 SLAM 지도를 사용한다.
- `python3 compare.py BASELINE_TRIAL CANDIDATE_TRIAL`은 최종 평가 파일에서 맵 해시를 대조하고 그 맵에서 실제 상자에 부착한 ID만 집계한다. ‘발견’은 정책의 ID 등록이고, ‘접근’은 등록 상태에서 실측 거리 1.5m 이하를 만족한 첫 시각이다. 둘 다 찾지 못한 경우 두 상자 완료 시간은 미측정으로 둔다.

기존 R32 주행의 카메라 보정 시각, TF, LiDAR와 지도를 동기화해 검증했다. 원래 주행 경로에서 확인한 상자는 f6myvZ0l에서 3개, 8yVAosBO에서 3개, wevIgT2q에서 0개였다. 확인한 여섯 위치는 각 맵의 실제 상자 중심에서 4~28cm 이내였다. ‘본 면’은 카메라 위치·시야·반사로 추정하며 마커 ID는 별도 영상 판독기로 확인한다. [센서 재생 수치](sensor_replay.json)
