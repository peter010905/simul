# Mixed · 상자 면 관찰 이력 공유

8780에서 실행한 기존 **공간 맞춤 면 관찰**의 별도 시뮬레이션 수정판이다. 트랙의 정답 배치와 마커 ID는 주행 정책에 전달하지 않는다.

## 반복이 발생한 이유

랜덤 시드 3131517562의 첫 번째 상자에는 마커가 없었다. 기존 정책은 이 상자에 목표 2~13번을 연달아 보냈다. 첫 목표부터 다른 곳을 선택할 때까지 192.5초가 지났고, 로봇 중심이 상자 중심 2m 이내에 머문 시간은 165.6초였다. 원본 영상에는 서로 다른 네 방향에서 같은 파란 상자를 본 장면이 있다.

기존 코드에서 사각형으로 추정한 면은 카메라 관찰 기록을 조회하지만, 일반 표면 후보는 방향별 격자 칸과 그 주변에 보낸 목표 이력을 조회한다. 같은 물리적 면이 두 후보로 표현될 수 있다. 4·5번 목표는 추정된 두 면이었다. 6~13번은 모두 같은 상자의 일반 표면 후보였다. 4번은 주행 실패로 취소됐고, 5번은 도착 후 관찰 동작이 방향을 받지 못했다. 추정 면이 요청한 회전량 0도를 도착 처리기가 거부하기 때문이다.

## 변경

- 여러 시점에서 확인된 상자의 면 위치·폭·법선과 카메라 관찰 상태를 오도메트리 좌표에 저장한다. 일반 표면이 그 면에 속하면 같은 관찰 기록과 재시도 이력을 사용한다.
- 미관찰 면은 남긴다. 모서리에서는 인접한 미관찰 면을 우선하고, 한 격자 묶음에 다른 표면이 섞이면 남은 길이를 재검사한다. 두 물체 중 어느 쪽 표면인지 모호할 때는 일반 표면 검사를 유지한다. 추정이 일시적으로 끊기면 마지막 형상을 최대 45초간 사용한다.
- 추정 면에 도착하면 면 중심을 가로지르는 24도 관찰 회전을 요청한다. 목표를 보낸 사실만으로 관찰 완료를 기록하지 않는다.
- 기존의 32cm 지도 여유, Nav2 충돌 검사, 마커 접근 우선순위와 벽에서 새 장애물로 돌아가는 조건을 유지한다.

## 로그 재생과 회귀 검사

당시 저장한 SLAM 격자와 실제 선택된 격자 칸을 대조했다. 목표 6~13번의 원래 표면 중심을 모두 같은 좌표로 재현했다. 해당 로그에는 매 카메라 프레임의 LiDAR 끝점과 내부 관찰 상태가 없다. 저장된 RGB 프레임 시각, 자세, 지도 시야선을 이용해 당시까지의 노출을 복원했다. 거리 1.5m, 시선 25도 이내, 연속 0.4초 이상의 기록을 썼다. 재생은 당시 후보에 대한 필터 검사이며 새로운 주행 궤적은 계산하지 않는다.

| 재생 대상 | 결과 |
|---|---|
| 첫 맵 목표 6~13번 | 7·8·9·10·12·13번 제외, 6·11번 유지 |
| 직전 별도 완주 로그의 일반 표면 목표 3개 | 3개 모두 유지 |
| 이전 실물 로그의 F1·F2, 두 시점 | NavFn 경로 4/4, 경로상 최소 지도 여유 40.3~51.0cm |
| 회귀 검사 | 총 14개 통과. 이웃 장애물·미관찰 면 보존, 도착 후 회전, 벽에서 가운데 장애물로 복귀 포함 |

## 별도 작업공간에서 실행 준비

ROS 2 Jazzy VM에서 기존 공간 맞춤 정책의 소스 작업공간을 입력으로 쓴다.

```sh
python3 install.py ~/flow_v3_r32_adaptive_ws ~/flow_v3_r32_shared_face_final_ws
cd ~/flow_v3_r32_shared_face_final_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select osp_mission
source install/setup.bash
```

검증한 VM에는 이미 빌드되어 있다. 8780 시뮬 보드의 **Mixed · 상자 면 관찰 이력 공유**로 선택할 수 있다.

## 같은 맵의 실제 Gazebo 주행

시드 3131517562에서 같은 월드 파일과 시작 자세로 재주행했다. 기존판이 마커 없는 상자에 관찰 목표 12개를 보냈고, 수정판은 4개를 보냈다. 상자 반경 2m 안의 회차 전체 체류 시간은 176.3초에서 52.4초로, 그 반경 안의 이동 거리는 19.53m에서 6.07m로 줄었다. 저장 영상에서 수정판이 상자의 남·서·북·동 네 방향을 본 장면을 각각 확인했다. 세 ID 등록 및 1.5m 이내 접근을 모두 마치는 데 기존판은 449.9초, 수정판은 231.6초가 걸렸다. 범퍼는 두 회차 모두 0회였다. VM에서 동시에 다른 실험이 실행될 수 있으므로 시간 비교에는 각 월드의 시뮬레이션 시계를 사용했다.

## 추가 5회 결과

전체 5회 중 2회에서 세 ID 등록과 1.5m 이내 접근을 모두 달성했다. 첫 회차는 같은 맵 재시험이고 나머지 새 맵은 1/4회 완주했다. 범퍼 이벤트 합계는 0회다. 별도 기존판 무작위 3회는 2회 완주했다. 정책간 동일 맵 비교는 첫 회차 하나뿐이다.

| 회차 | 시드 | 실제 등록·접근 ID | 시뮬 시간 | 범퍼 |
|---|---:|---|---:|---:|
| 1 | 3131517562 | 7, 32, 103 | 231.6초 | 0 |
| 2 | 1738834717 | 32, 103 | 600.0초 | 0 |
| 3 | 4043387270 | 32, 103 | 600.0초 | 0 |
| 4 | 2536958923 | 7, 32, 103 | 349.4초 | 0 |
| 5 | 3055713613 | 32, 103 | 600.0초 | 0 |

두 번째 회차의 벽 7번은 카메라 재판독에서 47프레임 잡혔지만 모두 6~9픽셀이었다. 세 번째 회차의 상자 7번은 로봇이 0.935m까지 접근했으나 근거리에서 인쇄면 앞쪽을 보지 못했다. 해당 상자를 향한 6개 목표는 모두 일반 표면으로 생성됐다. 원본 영상에서 이 ID를 판독한 39프레임은 5.9~9.6m에서 기록됐다.

재생에 쓰지 않은 기존판의 나머지 두 무작위 맵에서는 당시 선택했던 일반 표면 목표 25개 중 1개, 29개 중 22개가 이미 관찰한 면으로 분류됐다. 이 수치는 원래 궤적 위의 필터 판정이다. [회차별 수치](results.json)

다섯 번째 회차는 동쪽 벽의 7번까지 세 ID 전부를 등록했다. 7번 등록은 507.52초, 접근 명령은 572.02초였다. 600초 제한까지 최단 4.74m로 접근 기준에는 미달했다.
