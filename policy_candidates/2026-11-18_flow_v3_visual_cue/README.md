# 흑백 사각형 재관찰 단서의 오프라인 재생

보드의 Flow v3 surface sweep에서 파생한 실험 후보. 입력은 250×250 OAK-D 영상과 카메라 보정값이다. 기존 디코더가 찾은 사각형에서 밝은 바깥 여백, 어두운 테두리, 내부의 가로·세로 밝기 변화를 검사한다. 판독 가능한 ID가 없을 때 비슷한 크기와 위치의 후보가 0.35초 안에 두 프레임에 나타나면 카메라 각도만 제안한다. 해당 위치에서 4×4 사전 ID가 검증되면 단서를 생략한다. 재생에서는 주행기 취소, 실제 회전, 거리 추정, ID 등록을 실행하지 않았다.

| 실물 영상 | 프레임 | 첫 조건(3프레임 연속) | 수정 조건(0.35초 내 2프레임 및 4×4 배제) |
|---|---:|---|---|
| 17:08 벽 103번 | 1,943 | 단서 없음 | 123.88초에 단서. 첫 18px 판독 123.98초. 후보 중심 (123,146), 최소 변 25px |
| 이전 7번 | 3,607 | 단서 없음 | 단서 없음. 첫 18px 판독 220.47초 |
| 17:02 휴대폰 4×4 | 516 | 4회 | 19.20초에 1회. 원본 검토 결과 휴대폰 표식을 가리킴 |
| 16:40 추가 주행 | 4,533 | 단서 없음 | 단서 없음 |

17:08 영상에서 후보 프레임을 직접 확인했다. 마커는 이미 화면 중앙에 가까웠고 조기 신호의 이득은 한 프레임이었다. 같은 주행의 출발 후 90초 동안 후보 신호는 0회였다. 전체 영상에 물체별 정답은 없으며, 재생에서 출력된 단서 횟수와 실제 회전 횟수는 다르다. 16:40 영상에서 오프라인 기준 디코더가 읽은 7번은 독립 확인·접근 결과로 집계하지 않았다. 수정 조건은 이 영상들을 본 뒤 선택했으므로 별도 영상에서 일반화 검증이 필요하다. 보드 기본 정책은 기존 버전이다.

`results.json`은 각 조건의 프레임 수, 영상 시각, 판독 ID, 후보의 시각·중심 픽셀·최소 변 길이를 담는다. 최종 후보를 별도 작업 공간에 빌드하고 환경을 불러온 뒤 `python3 replay.py OUTPUT_DIR RUN_DIR ...`로 재생할 수 있다. 런타임 검사 399개를 통과했다.
