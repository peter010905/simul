# Mixed · 꼼꼼 탐색 후보

기존 `flow_v3_r32_full_box_ws`는 보존하고 `flow_v3_r32_thorough_ws`를 별도로 설치했다. 실물 보드의 **Mixed · 꼼꼼 탐색** 버튼으로 선택할 수 있다. 버튼을 누르기 전까지 로봇은 출발하지 않는다.

## 변경

- 화면 가장자리에서 잘린 흑백 인쇄 테두리의 최소 높이를 14→12픽셀, 검증된 변 길이를 10→8픽셀로 완화했다. 흰 여백·검은 테두리·내부 비트 변화·측정된 세 변의 명암 검사는 유지한다. ID 확정과 1.5m 접근 판정은 기존 로직 그대로다.
- LiDAR 깊이와 결합된 후보 3회 검출 조건을 유지하고, 원거리 위치 흔들림을 거리 비례 최대 30cm까지 묶는다. 후보 기억 시간은 20→45초, 재관찰 가능 시간은 16→30초다. 로봇이 해당 면을 지나쳤으면 안전한 지도 경로로 원래 관측한 쪽에 돌아가서 바라본다.
- 서로 다른 LiDAR 시점에서 확인된 상자만 조사한다. 네 면의 관찰 지점이 모두 안전하게 연결되면 기존 4면 관찰을 수행한다. 전체 순환이 불가능하면 비용지도에서 도달 가능한 면의 관찰 지점을 고른다. RGB에서 실제로 본 면은 재방문하지 않고, 실패한 목표는 35초 뒤 재평가할 수 있다. 마지막 45초에는 새 상자 조사를 시작하지 않는다.
- `hybrid_goals.jsonl`에 선택된 상자 관찰의 `box_view_scope`(`full_ring` 또는 `reachable_face`)를 기록한다. Nav2와 범퍼·충돌 검사는 유지한다.

## 검증

- VM의 ROS Jazzy 작업공간에서 `osp_mission` 빌드와 새 정책 모듈 로딩 성공. 합성 점유 지도 4개 검사: 네 면 연결, 일부 차단, 전부 차단/미확인 상자, 지나친 테두리 후보 복귀 모두 통과.
- 기존 실물 기록 `20261119T093822-c7a5f53af4`의 RGB를 0.5초 간격으로 **727프레임** 재생했다. 테두리 후보가 하나 이상 잡힌 프레임은 **80→84**, 이미 ArUco가 판독된 마커 위치와 겹친 프레임은 **57→59**였다. 새로 잡은 네 프레임 중 두 프레임에는 판독된 ID가 없었다. 이 둘은 실제 먼 마커인지 오탐인지 판정할 수 없다.
- 같은 기록의 `/mission/anonymous_print` **102건**을 재생했다. 첫 3회 연속 후보 시각은 기존과 새 버전이 **같았다**. 따라서 이 기록에서 더 빨리 마커를 찾았다는 증거는 없다.
- 초기 대시보드 제어 테스트 **18개** 통과. 이후 실제 주행 `20261119T102346-b814220173`은 약 42초에 종료됐으나 실제 정지 확인이 실패해 `stop_unverified`로 기록됐다. 목표는 2개뿐이었고 상자 관찰 목표는 0개였다. 마커 수·완주 성능은 **미측정**이다. 읽기 전용 재확인에서는 로봇이 정지했고 주행 감독기와 launch가 종료돼 있었다.

## 재현

기존 FullBox 작업공간의 `src/osp_mission/osp_mission`을 입력으로 `stage.py`를 실행한다. `stage_workspace.py`로 별도 ROS 작업공간에 생성된 후보 모듈을 복사한 뒤 `colcon build --packages-select osp_mission --symlink-install`한다. 원본 패키지를 수정하지 않는다. `test_thorough.py`, `replay_borders.py`, `replay_print_memory.py`는 주행 명령을 보내지 않는 검사다.
