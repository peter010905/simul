# Mixed · 각진 구조 우선

사진 `IMG_4124.HEIC`·`IMG_4125.HEIC`의 구조는 독립된 작은 상자보다 벽에 붙은 직각 돌출부에 가깝다. 기존 `ThoroughBox`는 지도에서 작은 분리 장애물의 네 면을 얻고 두 LiDAR 시점으로 상자를 확인한 뒤에야 관찰한다. 벽에 이어진 돌출부는 이 조건을 통과하기 어렵다.

이 후보는 기존 `flow_v3_r32_thorough_ws`를 보존하고 별도 `flow_v3_r32_corner_ws`에 설치했다. 지도에 실제로 찍힌 두 직교 LiDAR 선분이 한 모서리에서 만나는 경우 **임시 사각형 가설**을 만든다. 0.4초 이상 떨어진 두 영상 시점에서 같은 코너가 유지돼야 관찰 대상으로 삼는다. 독립된 상자로 확정됐으면 기존 네 면 관찰을 우선한다. 임시 가설에서는 비용지도와 지도상 경로가 모두 안전한 면으로만 이동한다. 길이 아직 없는 성긴 지도에서는 로봇의 현재 위치에서 코너 쪽으로 제자리 회전해 추가 정보를 얻는다. 실제 카메라 시야와 LiDAR 끝점으로 관찰한 면은 다시 고르지 않는다. 실패한 면은 35초 안에 반복하지 않고, 120초 안에 최대 두 번 시도한다. 마커 ID 판독, 1.5m 접근 판정, Nav2 충돌 검사는 기존 정책을 유지한다.

**네 면 관찰은 목표이지 보장이 아니다.** 사진 같은 벽 부착 돌출부의 뒷면은 물리적으로 막혀 있을 수 있다. 이 후보는 지도에서 새 면이 드러날 때마다 접근 가능한 면을 다시 평가하며, 미관측·차단 면을 통과 가능한 공간으로 가정하지 않는다.

## 확인한 범위

- 최근 실물 주행 `20261119T102346-b814220173`은 약 42초에 끝나 `policy_decisions` 지도 2장만 남겼다. 두 번째 지도에서 코너 후보 1개를 찾았다. 기존 실행의 `hybrid_goals.jsonl`에는 상자 면 관찰 목표가 0개였다. 새 후보는 같은 성긴 지도에 **코너 방향 제자리 관찰 목표 1개**를 낸다. 이는 후보 트랙에 두 번의 관측이 있다고 가정한 오프라인 재생이지 실제 출발 결과가 아니다.
- 이전 실물 주행 `20261119T093822-c7a5f53af4`의 결정 지도 28장에서는 코너가 보이는 지도가 8장, 합계 후보 11개였다. 두 번 관측된 트랙을 가정했을 때 이동 가능한 관찰 지점이 있는 지도는 4장이었다. 실제 카메라 관찰·목표 실행 시간·마커 탐지 증가량은 측정하지 않았다.
- 합성 지도 4개 검사에서 직각 코너 관찰, 미확인 코너·막힌 경로 거부, 직선 벽 제외, 경로가 부족한 경우 제자리 관찰과 다른 면 선택을 확인했다. 보드 제어 검사 21개 통과.
- 직전 주행 상태는 `stop_unverified`였으나 읽기 전용 재확인에서 `stationary=true`, 실행 중인 감독기와 launch는 없었다. 안전 신호 `active_hazard_types:1`이 있어 이 후보로 실물 주행은 하지 않았다.

## 재현

`stage.py`에 기존 꼼꼼 탐색 패키지 `~/flow_v3_r32_thorough_ws/src/osp_mission/osp_mission`과 새 staging 디렉터리를 전달한다. `stage_workspace.py`로 새 `~/flow_v3_r32_corner_ws`에 복사하고 `colcon build --packages-select osp_mission --symlink-install`한다. `test_angular_box.py`는 합성 지도만 사용하며 로봇 명령을 발행하지 않는다.
