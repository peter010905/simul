# Flow v3 · MPPI

2026년 11월 17일에 실물에서 사용한 Flow v3에 R32의 경로 추종 방식을 적용한 별도 후보입니다. 체감 속도와 정지의 원인을 구분하기 위해 실물 오도메트리, 저장 지도 재생, 동일 지도 자율 탐색, 동일 목표점 주행을 비교했습니다. 측정값은 [benchmark.json](benchmark.json)에 있습니다.

## 적용 범위

- 목표 선택은 Flow v3의 `edge` 탐색과 `face_intent_v2` 가중치를 사용합니다. 코너에서는 MPPI가 앞으로 움직이며 회전하는 후보 궤적을 함께 평가합니다. 전진 상한은 0.25m/s, 회전 상한은 0.50rad/s입니다. 경로 정렬 가중치는 3이고, 목표 방향 비용은 도착 0.25m 이내에서 적용합니다.
- 이동 목표를 수행하는 동안 8초간 6cm의 이동이 없으면 재계획합니다. 최근 2.5초의 오도메트리에서 0.15rad 이상 방향이 바뀌고 마지막 샘플이 1초 이내면 최대 16초까지 정렬을 허용합니다. Nav2도 회전을 진행으로 인정합니다. 경로 추종 중 Nav2 내부의 자동 90° 회전을 제거하고, 추종 실패는 Flow v3로 반환해 다음 목표를 고릅니다.
- 마커 사전은 Original, 판정은 18픽셀 이상·3프레임입니다. 실물 설치본 간 파일 비교에서 마커 탐지·접근 및 탐색 점수 코드가 일치했습니다. 범퍼, 후방 확인 후 후진, 낭떠러지·스톨 중단, 원시 스캔 충돌 감시 및 속도 평활화는 기존 경로를 사용합니다. 로봇 외곽선을 포함한 MPPI 충돌 비용도 활성화됩니다.
- R32에서 참고한 버전은 `a40cbdf`입니다. 해당 버전의 전진 상한은 0.25m/s, 회전 상한은 0.65rad/s입니다. 이번 비교는 같은 속도 제한에서 어제 v3와 개선판을 실행했습니다.

## 실물 로그와 코드에서 확인한 병목

| 지점 | 관측 및 해석 |
|---|---|
| 주행 중 방향 정렬 | 11월 17일 실물 265.93초 중 이동 163.07초, 제자리 회전 86.45초, 정지 16.33초였습니다. 제자리 회전 중 62.76초가 Nav2 주행 도중이었습니다. 기존 제어기는 경로 방향과 45° 이상 어긋나면 먼저 돌고, 곡률·장애물 비용·도착 거리에 따라 감속합니다. |
| 복구 재시도 | 11월 18일 실물 주행의 정체 구간에서 98초간 순변위는 약 4mm였고, 내부 90° 복구 회전이 11번 실패했습니다. 새 제어 흐름은 이 자동 회전 경로를 호출하지 않습니다. 같은 실물 장애물에서의 탈출은 아직 검증 전입니다. |
| 탐색 후보 계산과 기록 | 성공 주행 27장과 정체 주행 19장을 VM에서 재생했습니다. 후보 생성 시간의 중앙값은 각각 48.2ms와 34.9ms, 95백분위는 69.0ms와 35.6ms였습니다. 가중치로 후보를 고르는 단계의 95백분위는 0.11ms 이하, 압축 로그 저장은 약 4ms 이하였습니다. 이 측정은 지도 입력이 준비된 뒤의 계산 비용입니다. 센서 대기·TF 대기·회전은 별도로 발생합니다. |
| 남은 취약점 | Flow v3는 실패한 목표 반경 45cm를 60초간 제외합니다. 서로 다른 목표가 같은 좁은 출구를 공유할 때 다시 막힐 수 있습니다. MPPI는 매 제어 주기에 후보 2,000개를 56단계 예측합니다. VM의 20Hz 제어 주기 경고와 좁은 구간의 경로 이탈은 실물에서 함께 확인할 항목입니다. |

## 시뮬레이션 측정

Gazebo `robust_demo`의 같은 시작 자세와 지도(seed 8000001), 320px 카메라, 실제 주행용 Nav2 설정, 동일 가중치를 사용했습니다. 두 번째에는 실행 순서를 뒤집었습니다. 실물 도메인과 분리된 VM에서 한 번에 한 정책을 실행했습니다.

자율 탐색은 시작 후 50초를 관찰했습니다. 오도메트리 기준 선속도 절댓값 0.02m/s 초과를 이동으로, 그 이하에서 각속도 절댓값 0.08rad/s 초과를 제자리 회전으로 분류했습니다. 출발 전을 제외하고 0.5초 이상 연속 정지한 횟수를 셌습니다. 각 실행의 목표 선택은 달라질 수 있습니다.

고정 경로에서는 탐색기를 대기시킨 뒤 같은 세 좌표와 도착 방향을 Nav2로 보냈습니다. 시간은 첫 구간 시작부터 마지막 도착까지의 오도메트리 시뮬레이션 시간입니다. 도착 허용 오차는 두 제어기 모두 0.25m·0.25rad입니다.

두 번의 평균입니다.

| 지표 | 11월 17일 Flow v3 | Flow v3 · MPPI |
|---|---:|---:|
| 같은 3개 목표 도착 시간 | 20.04초 | 18.02초 |
| 같은 목표, 주행 거리 | 4.16m | 4.38m |
| 50초 자율 탐색 이동 거리 | 6.70m | 9.43m |
| 50초 자율 탐색 시작점에서 순변위 | 6.44m | 7.51m |
| 제자리 회전 / 완전 정지 시간 | 13.37초 / 3.55초 | 7.15초 / 2.01초 |
| 출발 후 0.5초 이상 연속 정지 횟수 | 3회 | 1회 |
| 자율 탐색 범퍼 보고 / 센서 중단 | 0회 / 0회 | 0회 / 0회 |

고정 경로 시험에서 두 버전 모두 매번 세 지점에 도착했습니다. 개선판은 조금 더 긴 궤적을 따라 평균 10.1% 빨리 도착했습니다. 두 번째 고정 경로에서 0.2초 간격 오도메트리로 추정한 각가속도 절댓값의 95백분위는 0.64에서 0.39rad/s²로 줄었습니다. 자율 탐색 중 20Hz 제어 주기 경고는 기존판 0·0회, 개선판 3·1회였습니다. 50초 내 확인한 마커는 두 버전 모두 0개입니다. 시뮬레이션의 출발 셀 완화 반경은 기본 0m이고, 실물 구동 및 지도 재생은 0.30m입니다. 정책 테스트 385개와 보드·실행기 테스트 38개를 통과했습니다.

전체 마커 미션 완료율, 실물 완주 시간, 좁은 문에서의 경로 여유는 별도 검증이 필요합니다.

## 실행

- 실물 보드의 **Flow v3 · MPPI 구동** 또는 Mac에서 `./robot.sh start-v3-mppi`를 선택합니다. 정지는 `./robot.sh stop`입니다. `./robot.sh dry-run-v3-mppi`는 연결 없이 선택한 작업 공간과 명령을 출력합니다.
- 빌드는 VM에서 `python3 policy_candidates/2026-11-18_flow_v3_mppi/build.py --workspace ~/face_intent_v3_mppi_ws --test`로 재현할 수 있습니다. 기존 설치를 보호하기 위해 새 작업 공간이 필요합니다.
- 측정은 각 작업 공간의 `install/setup.bash`를 불러온 뒤 `ROS_LOCALHOST_ONLY=1`과 별도 `ROS_DOMAIN_ID=184` 또는 `185`에서 `measure_transit.py OUTPUT_DIR`를 실행합니다. 동일 세 목표 시험은 `--fixed-route`, 기록 지도 재생은 `profile_decisions.py --focal 199.2552947998047 PATH_TO_POLICY_DECISIONS`를 사용합니다. 이 VM에서 Gazebo 전송은 Cyclone DDS와 `~/cyclonedds.xml`을 사용했습니다.
