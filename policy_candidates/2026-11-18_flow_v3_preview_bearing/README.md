# OAK-D 미리보기에서 마커 방위를 지도에 옮기는 방법

17:43 주행에서 103번을 발견하기 전에 처음 선택한 면이 기록 좌표와 49.8cm 차이 났다. 두 점은 모두 같은 오도메트리 좌표계에 있었다. 로그에 저장된 250×250 미리보기의 수평 초점거리 199.26픽셀을 그대로 사용하면 회전 중 고정된 벽 무늬의 방위가 움직였다.

## 17:43의 오차 분해

61.388초의 표식 중심은 x=224.75였고, 기존 계산에서는 광축에서 오른쪽 26.90도였다. 차체 자세를 더한 고정 좌표계 방위는 −110.75도였다. 62.192초 첫 ID 판독 프레임에서는 같은 면의 고정 좌표계 방위가 −96.06도로 계산됐다. 두 시점 사이에 카메라 위치가 이동한 거리는 약 2.2cm였다. 첫 선택 프레임의 이미지와 라이다 헤더 차이는 약 47ms였다. 기존 렌즈 왜곡 계수만 적용해도 첫 프레임의 각도 변화는 0.36도에 그쳤다.

17:08 로그 첫 90초 내 배경 특징점만 사용했다. 차체 이동이 2.5cm 미만인 회전 영상 쌍에서 양방향 광류 검사와 배경 평면 변환 검사를 통과한 점을 썼다. 배경의 픽셀 이동과 촬영 시각에 보간한 차체 회전량이 맞도록 수평 초점거리를 추정했다. 55쌍, 3,623개 특징점 대응에서 배율 1.79를 얻었다. 이 값을 고정해 나머지 주행을 평가했다. 세 주행에서 개별 추정한 값은 1.77, 1.75, 1.77이었다. 17:43의 배경 회전 오차 중앙값은 7.54도에서 0.19도로 줄었다. 녹화만으로 드라이버가 이 보정값을 출력하게 된 세부 경위는 확인할 수 없다.

수정한 재관찰 후보는 이 카메라 프레임·해상도·기존 보정값이 일치하는 경우에만 수평 초점거리 356.67픽셀을 적용한다. 라이다 점을 영상에 투영할 때와 영상에서 라이다 면으로 쏘는 광선 양쪽에 같은 값을 사용한다. 원본 ID 판독기, 최초 관측 기준 좌표 및 판정 반경은 그대로 두었다. 이는 오프라인 재관찰 후보의 수정이다.

보정 후 61.388초의 수평 방위는 오른쪽 15.82도가 됐고, 고정 좌표계 방위는 두 프레임에서 각각 −99.67도와 −100.04도였다. 기존 첫 재관찰 위치는 두 프레임의 면 추정값을 평균한 (−3.734, 2.110)m였고, 수정 후에는 (−3.401, 1.931)m였다. 첫 ID 관측에 저장된 기준점은 (−3.291, 1.883)m다. 같은 모델로 첫 선택과 첫 판독 영상을 각각 투영한 위치 차이는 50.5cm에서 0.9cm로 줄었다. **0.9cm는 영상 사이의 일관성이고, 기록 좌표와의 차이는 12.0cm다.** 기록 좌표에도 원래 카메라 보정이 쓰였으며 독립 실측 정답은 없다.

4회 모두 동일한 11,600개 동기화 프레임을 사용했다. 30cm 이내이면서 관찰자를 향하는 같은 면을 ID 판독 전 첫 목표로 고른 주행은 3회에서 4회가 됐다. 즉시 재관찰 요청은 두 버전 모두 총 5회였다. 17:08은 이전 비교와 동일하게 영상과 라이다로 추정한 기준점을 사용했다. 17:37은 첫 선택 시각도 바뀌었다. 실물의 실제 접근 시간은 측정하지 않았다.

## 재현

Flow v3 surface sweep의 ROS Jazzy 환경에서 실행한다. BASELINE에는 기존 면 기억 실험의 주행별 JSON, RUNS에는 네 원본 주행 폴더를 넣는다. fit_preview.py 출력의 배율별 각도 오차 곡선을 요약한 값은 background_calibration.json에 있고 전체 재생 집계는 results.json에 있다.

```sh
python3 fit_preview.py calibration_grid.json RUNS...
python3 replay_bearing.py BASELINE OUTPUT RUNS...
python3 audit_projection.py RUN_1743 61.2 62.3 103 projection_pairs.json
python3 -m unittest -v test_preview
```
