# Mixed v1.5.2 r2 · 이동 중 벽 관찰

v1.5.1은 보존하고 별도 `flow_v152_wall_transit_r2_ws`를 만든다. 시뮬 기본 `sim-camera.sh`와 실물 기본값은 바꾸지 않는다. 이 후보는 **동일 맵 개발 회귀1회 완료** 상태다. 벽 관찰6회·새 프레임33장·복귀6회는 확인했지만 벽7을 놓쳐 완주 개선은 확인하지 못했다. 일반 성능이 더 좋다고 확정하지 않았다. [동일 맵 주행 비교](../../experiments/2026-11-21_wall_transit_v152/README.md).

## 동작

- 목적지로 이동하는 동안 2초 간격으로 주변의 안 본 벽 유사 면을 조회한다. 기존 `surface_cells`의 SLAM·관측된 바닥 분류를 사용한다. 의미론적으로 진짜 벽임을 보장하는 분류기는 아니다.
- 현재 시야 바깥, 거리0.42~3.5m, 정면성0.6 초과, 알려진 자유 공간의 시선이 확보된 미관찰 면0.6m 이상을 찾는다. 숨겨진 마커·완성 지도·시뮬 정답은 입력하지 않는다.
- 현재 위치의 알려진 자유 공간 여유0.32m가 있어야 회전을 요청한다. Nav2가 기존 충돌 검사를 수행한다. 로봇 footprint·inflation·센서 범위를 줄이지 않는다.
- Nav2 이동 취소의 응답을 받은 뒤 최대100° 짧게 돌아보고, 최소0.8초 및 새 처리 프레임3장을 기다린다. 영상이 부족하면2초 뒤 관찰 실패로 기록한다. 명령만 내린 것을 인식·관찰 완료로 처리하지 않는다.
- 새 마커 정보가 생기면 정상 focus/approach 선택으로 돌아간다. 없으면 원래 NavigateToPose 목표를 재개하며 도착 후 할 원래 면 관찰 예약도 보존한다. 단순한 면 예약 때문에 이동 중 벽 보기가 차단되지 않도록 구분했다.
- 실제 마커 접근·focus·판독 후보 재방문과 접촉·안전 복구는 보호한다. Spin 실패는 기존 안전 복구를 사용한다. 취소 응답 전 재개하지 않고 동작 결과를 잃으면 미션을 중단한다.
- 25초 간격, 최대6회,35초 예산을 사용한다. 예산은 실제 관찰 시간과 경로 복귀 회전까지 포함한 추정값 중 큰 값으로 차감한다. 작업당10초가 지나면 취소를 요청하되 응답이 지연되는 시간을 임의로 성공 처리하지 않는다. 동일 물리 면은 odom 위치·방향으로 중복 억제한다.
- 마지막 벽 관찰 예산을 내부 새 면이 우회하던 조기 반환을 고쳤다. `probe_only`는 여전히 내부 면 조회만 하고, 확인된 마커 접근은 표면 스케줄보다 먼저 선택된다.

벽 예산은 목표를 재선택하는 시점의 우선순위다. 진행 중인 긴 내부 이동 때문에 실제 벽 전환이 늦어질 수 있으며, 마지막90초 전체를 확보하는 강제 시간표와는 구분한다.

고정 RGB 카메라라 옆을 보려면 차체 방향을 잠깐 바꿔야 한다. 계속 직진하면서 카메라만 좌우로 움직이는 방식은 아니다. 짧은 관찰의 비용을 제한하면서 기존 주행에 벽 정보를 더하는 후보이다.

## 검증과 한계

새 선택·마커 보호·실제 Mission 콜백·영상 증거·취소/복귀·시간 한도 검사20개와 기존 동작 제어 검사9개, **29개 통과**. 별도 스테이지 빌드도 통과했다. 기하 제안 검사와 실제 Nav2 경로 계획의 성공은 구분한다.

기존 `NearPassInspection` 기하 검사3개는 변경 전 v1.5.1에서도 똑같이 실패했다. 예를 들어 테스트는1.2m 범위를 기대하지만 동결 소스의 한도는1.4m이다. 원본을 고쳐 통과시킨 것으로 표시하지 않았다. 새 후보는 이 옛 `choose`를 호출하지 않고 별도 `WallTransitInspection`과 그 회귀 검사를 사용한다.

개발 첫 회차는 일반 면 예약까지 보호하는 조건을 잘못 넣어88.6초에 중단·보존했다. 이는 정책 구현 버그에 의한 개발 중단이며 완료 비교에서 제외한다. r1 스테이지는 보존하고 r2를 새 경로에 만들었다. 시작 전 실행기의 집계 모듈 이름 충돌도 수정했으며 그 오류에서는 ROS 미션이 시작되지 않았다.

실제 로봇 검증은 하지 않았다. 벽 유사 분류의 오차, SLAM 변화, 추가 정지 비용, 다른 배치의 완주율은 주행 비교로 확인해야 한다. 6~10px 후보 생성기·18px ID 등록·센서 동기화·1.5m 독립 평가·1.3m 영상 증거 기준은 그대로다.

## 실행

준비된 Mac/VM에서 `bash sim-wall-transit.sh 112601`로 동일 대형 트랙의 알려진 실패 배치를 실행한다. 다른 보존 맵112602~112605도 명시적으로 선택할 수 있다. 공통 lock이 사용 중이면 새 주행을 거부한다.

새 환경에서는 `python3 install.py <동결 v1.5.1 workspace> <새 workspace>`로 소스를 복사한 뒤 Jazzy underlay에서 `colcon build --symlink-install --packages-select osp_mission --executor sequential`을 실행한다. 원본을 덮어쓰지 않는다. `wall_transit_manifest.json`은 변경하지 않은 파일과 네 수정/추가 모듈의 해시를 남긴다. Launch에서 `allow_mid_route_wall_inspection=true`가 필요하다.
