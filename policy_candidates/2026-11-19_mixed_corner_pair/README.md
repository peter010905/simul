# 확인된 상자의 두 면을 한 시야에 담는 Mixed 후보

기존 v2의 두 시점 상자 확인, 관측한 면 기억, 실제 접근·마커 등록 절차를 사용한다. v2는 가려진 쪽과 직선 이동 거리를 기준으로 모서리를 골랐다. 새 후보 v3는 통행 여유가 있는 지도 셀을 따라 구한 이동 거리와 회전을 고려한다. 확인된 상자에서 이웃한 두 미관측 면의 중심이 실제 카메라 시야에 여유 있게 들어오고 각각 1.45m 이내에 있으며 시선이 열려 있으면 두 중심의 중간을 조준한다. 이동 목표를 보낸 것만으로 확인한 면이 늘어나지는 않는다.

## 같은 센서 시각의 선택 비교

R32의 별도 기록 두 건에서 카메라 보정 시각, 시야각, 라이다, TF, 비용지도와 SLAM 지도를 재생했다. 동일 시각에 두 정책 모두 목표를 제안한 경우를 대응시켰다. 목표는 실행하지 않았고 접근·등록된 마커와 실패 목표에 대한 제외 목록은 비웠다. 같은 상자를 여러 시각에 평가했으므로 표의 건수는 독립 주행 횟수를 뜻하지 않는다.

| 기록 | 같은 시각 | 두 미관측 면을 함께 볼 수 있는 위치 v2 → v3 | 평균 지도상 경로 v2 → v3 |
|---|---:|---:|---:|
| 8yVAosBO | 63 | 33 → 47 | 1.53m → 1.33m |
| f6myvZ0l | 59 | 19 → 29 | 1.86m → 1.61m |

[재생 집계](replay_results.json). 상자 오인·네 면 확인 종료·시야·가림·비용지도 우회 관련 테스트 8개를 VM에서 통과했다. 같은 랜덤 맵에서 v2와 v3를 실행하는 Gazebo 비교를 등록했다. 실측 결과가 나오기 전 자동 주행의 Mixed는 v2를 쓴다.

## 지도 좌표 검증

직전 완료 회차 BVOucwt9의 저장 좌표를 확인했다. 각 정책의 의사결정 시각에 기록한 SLAM 로봇 위치와 시뮬 실제 위치로 평면 강체 변환을 추정한 후, 마커 좌표를 변환해 오차를 구했다. 마커 좌표는 변환 추정에서 제외했다. v2는 7·32·103번의 위치 오차가 각각 1.5·1.4·1.7cm였다. 로봇 위치 정합 자체의 RMS 오차는 1.8cm였다. [좌표 평가](previous_map_check.json)

## 재현

VM에서 `python3 stage.py ~/mixed-box-views-v2/osp_mission ~/mixed-box-views-v3`로 별도 설치한다. Gazebo 비교는 트랙 실행기에 `TRACK_BASELINE_OVERLAY=~/mixed-box-views-v2`, `TRACK_MIXED_OVERLAY=~/mixed-box-views-v3`를 지정하고 `compare-mixed`를 실행한다. 센서 재생은 ROS와 Mixed를 로드한 환경에서 해당 버전의 오버레이를 PYTHONPATH 맨 앞에 두고 `python3 replay.py RUN_DIRECTORY`로 실행한다.
