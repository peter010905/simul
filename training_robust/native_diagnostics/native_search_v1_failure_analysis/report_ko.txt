Gazebo 실제 실패 분석 — native_search_v1

범위: 새로운 검증 배치 20개 × 2정책 = 40회. 성공 18회, 실패 22회.
저장된 평가 JSON, 실제 위치 궤적, 검출 관측, 정책 입력 스냅샷, Nav2 로그를 전체 대조했다.
영상은 대표 사례의 저장 프레임을 확인했다. 22개 영상을 처음부터 끝까지 모두 시청한 것은 아니다.

결론
1. 3회: 탐색 후보 생성기가 현재 로봇 위치를 고립된 셀로 판단하고 탈출 없이 회전을 반복.
   trial031: 129.646초부터 마지막599.646초까지 후보0, 95회 / 회전 명령100회.
   trial039: 86.443초부터 마지막596.443초까지 후보0, 103회 / 회전 명령108회.
   trial057: 83.307초부터 마지막598.307초까지 후보0, 104회 / 회전 명령109회.
   당시 지도상 중심-장애물 거리0.25~0.269m. 탐색용 safe grid는0.32m 이상만 허용.
   현재 셀 한 개만 강제로 safe=True로 만들지만 주위 셀은 막힌 채라 연결 영역이1셀.
   edge_policy.options의 safe.sum()<4 조기 반환과 mission의 selected=None→재회전 처리가 결합했다.
   세 회차 실제 스냅샷을 동결된 원본 옵션 생성기로 재실행해 모두 후보0 재현(replay.json).
   이는 물리적으로 탈출 불가능하다는 증거가 아니다. 회피 여유를 일괄 축소하는 해결도 검증되지 않았다.

2. 5회: 추가 근접 RGB 조건 때문에 완료되지 않음(trial021,025,028,030,051).
   각 회차 실제 ID3개, 지도 좌표 허용 오차, 실제1.5m 접근 충족 기록이 있다.
   그런데 구현은 이미지가 들어온 바로 그 시각에 추정 거리1.3m 이내인 관측을3번 요구한다.
   최소 실제 접근 거리와 읽힌 이미지의 거리는 다른 시간의 값이므로 서로 모순되지 않는다.
   사용자가 요구한 접근·ID 인식을 분리해 관리해야 한다.1.3m는 목표 여유 거리로 사용할 수 있으나
   추가 재인식을 종료 필수 조건으로 묶은 것은 요청보다 엄격한 구현이다.
   기존 실패를 임의로 성공으로 바꾸거나, 수정 후 성공률이 올라갔다고 계산하지 않았다.

3. 1회: 실제3개를 찾았지만 가짜 ID1023을 네 번째 목표로 등록(trial044).
   실제 ID는249/645/961.1023도5개 관측으로 등록되고 근접 인증까지 받음.
   1023의 추정 위치는645의 추정 위치와 약5.28cm 차이. 같은 물체 주변 중복 오인식 가능성이 높음.
   영상121.0초 프레임에서 Confirmed targets:4/3 확인(trial044_four_targets.png).
   MarkerApproach.complete는 len(targets)==3이므로 오등록된 ID가 남으면 완료 불가능.
   원본 RGB/검출 코너는 저장되지 않아 어떤 픽셀 패턴이1023을 유발했는지는 확정하지 못함.
   1023은 사전에 무조건 배제할 ID가 아니다. 실험 정답ID를 정책에 제공하는 해결도 사용하면 안 된다.

4. 13회: 위 구조적 정지/오등록 없이 마커 관측 또는 확정에 실패.
   전체 실패 회차에서 빠진 실제 마커는21건(회차 수와 다름).
   이 중15건은 원시 ID디코딩0회,5건은 디코딩했지만 accepted관측0회,1건은accepted1회뿐.
   5건은 실제1.5m 이내까지 지나갔어도 ID를 확정하지 못했다.
   - trial049 ID852 / trial050 ID370: 가장 가까운 위치는 마커 뒷면 쪽이고, 전체 궤적에서
     마커 정면 법선 기준±60도 관측 영역에 들어간 기록도 없음.
   - trial055 ID150:0.576m까지 접근했지만 그 순간 로봇 기준 방위 약-90도.
     해당 영상에서 정면 RGB에 마커가 보이지 않음. 접근만으로 시야가 확보되는 것은 아님.
   - trial023 ID172:47회 디코딩,accepted1회,최소 거리2.949m.후속 접근1회 기록은 있지만
     3개 관측 확정에 도달하지 못함.코드상 힌트는90초 만료,최대2번 시도 제한.
   기존 기록은 필터 거절 사유를 ID별로 저장하지 않으므로 작은 픽셀/깊이 누락 등 세부 원인을
   각 마커에 단정할 수 없다.작아진 합성 영상으로960px 원본 검출을 재현할 수도 없다.

수정 우선순위와 검증 방법
P0: 현재 위치가 탐색 여유 영역 밖에 있을 때 안전한 복구/재연결, 장시간 후보0 회전 감지.
    세 저장 스냅샷 회귀 확인 후 동일 배치 실제 Gazebo에서 탈출/충돌 여부 비교.
P0: 정확한 ID확정과 위치기반 접근 완료를 분리.사용자1.5m 기준을 유지하고
    런타임 추정 위치로 판단하되 평가에는 실제 궤적을 사용.실제 정답 좌표를 정책에 공급하지 않음.
P1: 동일 위치의 상충하는 ID를 보류·재확인하고 오등록 회복 절차 추가.
    잘못된 ID를 포함한4개에서 임의3개를 골라 성공 처리하지 않음.
P1: 미확정 관측의 재방문·정면 관측 계획과 마커가 붙을 수 있는 면의 관측 누락 보완.
    다음 진단 회차에는 ID별 픽셀 크기·깊이·필터 거절·카메라 pose를 저장.

이 보고서는 분석 결과이며, 위 수정의 성능 개선이 검증됐다는 의미는 아니다.
원본 실험과 결과는 보존했다.최종40회 독립 평가는 아직 사용하지 않았다.
